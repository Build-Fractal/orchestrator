### Dangerous Contradictions

- **[P0 blast-radius — "audit ALL unguarded set -e/pipefail" as a P0 deliverable]** — pipeline-reliability (Missed Opportunities §1; Rec 2 "scope-the-unguarded-command-audit-to-an-artifact," Priority P0) wants a *checked-in audit artifact* enumerating every pipeline in `rebuild-index.sh` + sourced libs (`lib/index-utils.sh`, `lib/graph-db.sh`), each unguarded one fixed-or-justified, with an AC that the artifact lists zero unjustified-unguarded pipelines. My review (Rec 2 "bound-P0-hotfix," Missed Opportunities §5) argues the opposite pressure: a P0 hotfix wants the *smallest correct change* (Principle XV Surgical Precision), and bundling a whole-script audit risks the hotfix growing past its proven-bug surface. **Why dangerous:** an open-ended "audit every pipeline, fix or justify each" can balloon `:117` (a one-line guard) into a multi-file refactor across sourced libs — exactly the scope-creep Principle XIV/XV warn against — and the ship date of the proven-bug fix becomes hostage to auditing pipelines that have no reproduced defect. Conversely, if we *only* fix `:117`, pipeline-reliability is right that the sibling-asymmetry class (`:40` guarded, `:117` not, nothing tested the difference) recurs. **Suggested cooperative resolution:** scope the audit to `rebuild-index.sh` + its *directly sourced* libs only (pipeline-reliability already bounds it this way in Rec 2's scope line — adopt that bound as binding), make the artifact a *grep-enumeration* (cheap, deterministic, no per-pipeline refactor), and split it: enumerate-and-classify ships P0 (small, mechanical); *fixing* a non-`:117` unguarded pipeline ships P0 only if it has a reproduced failure, else it lands as a justified-and-tracked row. This keeps Surgical Precision while closing the "guard was assumed, never enumerated" trap.

- **[grep-everywhere default-on vs token-budget governance]** — pipeline-reliability (Rec 1 "mandate-index-free-fallback-for-all-consumers," P0; Missed Opportunities §2/§9) wants the deterministic-grep-over-raw-files fallback wired into *every* index consumer as P0, plus (Rec 11) pulling FR-14's index-free degrade-to-grep partially into P0. My review (Rec 7 "budget-bound FR-6 and FR-12/FR-14 retrieval," Missed Opportunities §"no token-budget governor named") flags that grep-fallback *injects content into payloads* and must route through M036a's existing token-budget governor (SC-3/SC-7), or the fail-loud fix trades a silent under-load for a silent over-load — both Principle I (Context Minimization, "minimize *total* task tokens") violations. **Why dangerous:** "grep over raw files on every consumer, P0" with no budget governor named is an ungoverned content firehose shipping under hotfix urgency — the failure mode is a degraded inject that is now *loud and oversized*, blowing the Quick profile M031 deliberately right-sized and re-inflating total task tokens. **Suggested cooperative resolution:** adopt pipeline-reliability's all-consumers coverage as the *guarantee* but require every grep-fallback path to declare its token budget through the M036a governor; in P0, ship the *fail-loud + provenance header* on all consumers (cheap, no content firehose) and ship the *grep retrieval* itself budget-bounded — pipeline-reliability's "fallback against RAW files even with index+db deleted" regression (Rec 11) is compatible with this as long as the regression asserts hits *within budget*, not unbounded.

- **[fixture-byte-equality regressions as P0 across all surfaces]** — pipeline-reliability (Rec 3 "lock-regressions-at-fixture-byte-equality," P0; Missed Opportunities §4) wants every P0 regression to ship a committed fixture corpus + exact expected-output file asserted byte-for-byte (the `INDEXED:/SKIPPED:` summary line, the degraded-payload provenance header block, the freshness-flag output). My review treats fixture discipline as right (it aligns with Principle IX Reproducibility) but did not put it on the P0 critical path. **Why dangerous (mild — flagged for sequencing, not correctness):** byte-equality fixtures are the correct convergent default (this is a strong agreement, see below), but pinning a byte-stable expected-output file for the *provenance header* before that header's schema is locked (pipeline-reliability's own Rec 4 defers the schema to P1) creates an ordering hazard — you cannot byte-lock an output whose schema is still open. **Suggested cooperative resolution:** byte-equality fixtures ship P0 for the *deterministic, schema-settled* surfaces (the `INDEXED:/SKIPPED:` summary, the path-collision index count, the freshness flag); the provenance-header fixture ships *with* the header schema (pipeline-reliability Rec 4, P1) so the byte-lock and the contract land together. This is a sequencing reconciliation between their own Rec 3 and Rec 4, not a disagreement on the discipline.

### Tensions

- **[how loud is "loud" — provenance header tokens vs Context Minimization]** — pipeline-reliability's position: the provenance header (`source: index|grep-fallback|degraded`, `index_age`, `entries_considered`, plus a `schema_version`) is mandated *into the injected payload always* (Rec 8 "header always + stderr always," Missed Opportunities §3), and pinned as a versioned byte-stable contract. My position: the header is correct and Principle-II-serving, but every field added to *every* inject is a standing token cost against Principle I, so the header should be compact and the *hard gate* reserved for the single highest-stakes path (`comments` spec-amendment), not blanket. **Nature of tension:** productive — both want degradation visible; we differ on the marginal token weight of "always, full header" vs "always, minimal header." **Coordination needed:** agree the *payload* header is minimal (source enum + one age/count field), with the richer fields (`entries_considered`, `schema_version`) emitted to stderr/evidence-artifact rather than the payload. This satisfies pipeline-reliability's "agent must always be able to tell scoped knowledge from a degraded fallback" while honoring Context Minimization on the always-injected line.

- **[standalone P0 observability vs M038 living-docs / M040 freshness primitive]** — pipeline-reliability's position: treats FR-10 freshness contract and FR-5 provenance largely as standalone reliability invariants to harden now (Rec 9 content-hash freshness, Rec 11 pull index-free guarantee into P0). My position: §6 of the proposal honestly maps FR-10/FR-5 to M038 living-doc primitives and FR-7/FR-8/FR-12 to M040 surfaces; my central recommendation is to fold the *feature* half into M040 rather than re-specify it. **Nature of tension:** pipeline-reliability is optimizing for "fix the burning bug today, milestone-independent"; I am optimizing for "don't ship a second capture/freshness primitive M040 then has to reconcile." These are not contradictory — they partition cleanly along the proven-bug / feature line — but they *pull on the same FRs* (FR-5 has both a P0 fail-loud core and a P1 freshness-primitive tail). **Coordination needed:** explicitly bisect FR-5 and FR-10: the *fail-loud detection + minimal provenance flag* is P0 reliability (pipeline-reliability's lane); the *freshness-as-living-doc-primitive + content-hash contract wired into a standing doctor invariant* is the M038/M040 composition point (my lane). Both reviews already gesture at this — make the cut binding so neither half re-specifies the other.

- **[content-hash freshness as P0 vs deferred to the freshness primitive]** — pipeline-reliability's position: content-hash (not mtime) is the durable freshness signal and should be the contract now (Rec 9, P1 in their numbering but argued as load-bearing), because `orchestrator:update` re-installs and git checkouts rewrite mtimes wholesale. My position: I concur content-hash is correct (Principle IX) but placed the freshness *contract* in the P1/M040 track (Rec 10 "keep-DQ-1-index-demotion-out-of-P0"), keeping P0 to "the index *may be* stale and that is *loud*." **Nature of tension:** sequencing, not substance — we agree mtime is unreliable and content-hash is the durable signal; we differ on whether the full freshness contract is P0 or P1. **Coordination needed:** P0 ships the *detection that the index is stale/empty + loud warning* (which can use a cheap content-hash compare without the full doctor-wired contract); the *standing freshness invariant + doctor wiring + auto-rebuild-then-warn policy* (DQ-3) lands P1. pipeline-reliability's content-hash insistence is adopted as the *signal*; my P0/P1 boundary governs *how much machinery* ships when.

- **[vestigial-index doctor check — standing invariant vs one-time cleanup]** — pipeline-reliability's position: FR-11 should not just remove/alias the duplicate `.orchestrator/KNOWLEDGE-INDEX.md` / `knowledge.db` — it should add a standing `doctor` invariant that *asserts no second index/db exists* (Rec 10, Missed Opportunities §"vestigial-path trap"), because a silently-present second copy misdirects diagnosis. My position: I flagged FR-15's doctor check as *overlapping a queued paper-cut* (`papercut-doctor-knowledge-gap-surface.md`) and recommended one doctor check, one owner (Rec 8, Principle VIII No Dead Infrastructure / XI Single Source of Truth). **Nature of tension:** pipeline-reliability wants *more* doctor surface (a new no-vestigial-index assertion); I want the doctor surface *consolidated* to avoid two overlapping checks. These coordinate cleanly. **Coordination needed:** route pipeline-reliability's no-vestigial-index assertion *into* the same doctor-knowledge-gap check that FR-15 reconciles with the paper-cut — one doctor check that covers both "0-MEM on a mature project" and "second index/db exists" — so we gain the standing invariant without minting a second overlapping doctor surface.

### Safe Agreements

- **[determinism over embeddings is the activation guarantee]** — shared position: pipeline-reliability (Rec 6 "deterministic grep is the floor; embeddings only additive," DQ-2 resolution; Missed Opportunities §"corpus-gate evidence-artifact reproducibility") and my review (Rec 3 "defend-determinism / resolve DQ-2," Alignment §"corpus-gate index-independence preserved") converge hard: deterministic grep over raw files is the *guarantee* and the *only* input to the corpus-gate evidence artifact; embeddings, if ever added, are additive recall that never gates and never enters the receipt. Combined evidence: their reliability lane (nondeterminism breaks the reproducible trust receipt, costs tokens, needs a model) + my constitutional lane (Principle IX makes non-determinism a bug; the reproducible grep log is the corpus-gate's trust asset). Evidence strength: strong — two independent derivations, one operational one constitutional, reaching the identical invariant. Confidence: high. Joint recommendation: resolve DQ-2 *as a stated invariant in the brief*, not an open question. pipeline-reliability adds a concrete hardening I endorse: forbid the nondeterminism vectors (locale `sort` → `LC_ALL=C`, no wall-clock fields in the artifact body, stable file ordering) so the receipt is reproducible in fact, not just in aspiration.

- **[proven-bug fixes are genuine P0, milestone-independent]** — shared position: pipeline-reliability (Executive Summary; Rec 11 "keep §7 P0/P1 phasing — ship proven bugs milestone-independent") and my review (Executive Summary; Alignment §"P0/P1 phasing split"; Rec 1 "cleave-physical-split") agree the §7 split is correct: the five reproducible file:line-cited defects ship as a tightly-bounded P0 hotfix not gated on any milestone queue, and the larger activation build composes with M040. Combined evidence: pipeline-reliability's blast-radius framing ("trust recovery should not wait on a milestone queue") + my constitutional framing (Principle XIV No Speculative Complexity + XV Surgical Precision: the hotfix must not entangle with DQ-1/DQ-2/DQ-5/DQ-7/DQ-8 redesign questions). Evidence strength: strong. Confidence: high. One coordinated nuance: pipeline-reliability wants the index-free "fallback survives index+db deletion" regression pulled *partially* into P0 (Rec 11); I'd accept that specifically as a *test* (cheap, proves P-B) while keeping the full index-free retrofit of every consumer in P1 — these reconcile.

Evidence strength: strong on the *fail-loud-everywhere* coverage. Confidence: high on coverage; *medium* on the open coordination point — we agree all consumers must fail *loud*; we still need to settle (per the Tensions section) whether all consumers must also *grep-retrieve* in P0 (pipeline-reliability) or P0 ships loud-everywhere + grep-retrieve-budgeted (my lane). The *visibility* guarantee is the safe agreement; the *retrieval* scope is the coordinated tension.

Combined evidence: their byte-stability lesson (injected-payload contracts drift if not locked) + my composition-point framing (§6 promises this header to M034/M038; an unstable header makes that promise unkeepable). Evidence strength: strong. Confidence: high. Coordinated nuance (carried from Tensions): the *contract* is byte-stable and versioned; the *payload-resident* subset stays minimal for Context Minimization, with the full schema available via stderr/evidence-artifact and the locked fixture.
