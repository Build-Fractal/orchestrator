### Dangerous Contradictions

- **[capture-redesign-vs-the-alarm-that-catches-it]** — *activation-loop claims* (review §Missed Opportunities `[demand-signal-already-fired]`, L33; Rec 2 L64-69): promote the capture loop — G-1/FR-8 (Quick-default capture), G-4/FR-7 (capture command), G-3/FR-9 (two-store bridge) — into P0 co-primary trust recovery, because the field note proves the demand has already fired. *pipeline-reliability claims* (my review §Recommendations Rec 1/2/11, L67-69/87): P0 should be dominated by the *fail-loud observability* surface — FR-15's 0-MEM/degraded-source warning, the enumerated index-free fallback, the unguarded-command audit artifact — because that is the layer that would have *caught* the month-long silence regardless of which capture path was used. *Why dangerous (failure mode):* if P0 fills with new capture-command surface (a new `orchestrator:note` command, the two-store graduation step) and the observability FRs slip to "minimum to make the class visible," we re-ship the exact 2026 incident with a nicer front door — a project captures decisions through the new command, a *different* silent break (stale index, thin scope_tags, a second unguarded pipeline) eats them, and again **nobody is told**. The capture loop without the alarm is a graveyard with a *better* return path but no smoke detector. *Suggested cooperative resolution:* both belong in P0, but sequence the alarm *first within* P0 — FR-15 (0-MEM + `source: grep-fallback|degraded` warning) and the index-free fallback are the cross-cutting net that makes *every other* P0 fix verifiable, including activation-loop's capture command (its AC-1 "confirms the entry resolves in an inject" step literally depends on a working, observable inject path). Frame it: alarm is the substrate, capture is a load-bearing tenant — both P0, alarm has no dependencies and ships on day one.

- **[read-runtime-memory-live-vs-index-free-determinism]** — *activation-loop claims* (Rec 4 `[resolve-DQ-8-system-of-record-with-enforcement]`, L78-83): resolve G-3/DQ-8 toward **graduation (b)** as the default with live-read (a) only as opt-in augmentation, and concedes live-read "couples to CC's memory format and breaks runtime parity." *pipeline-reliability claims* (my review §Off-Base + P-B framing, and Rec 9): the system-of-record store must be the on-disk raw corpus the deterministic grep fallback resolves against; any path where the injector reads a runtime-specific memory shape *live* puts a non-deterministic, runtime-coupled source on the activation-guarantee path — the opposite of "the guarantee runs index-free over raw files." *Why dangerous:* if DQ-8 resolves toward live-read (option a) as anything other than strictly-opt-in, the grep fallback can no longer be the single deterministic floor — a consumer might "succeed" by reading CC memory and silently skip the raw-corpus path, reintroducing a fail-open the moment a non-CC runtime (or a memory-format change) returns nothing. *Suggested cooperative resolution:* we are already aligned — activation-loop explicitly picks graduation-as-default and quarantines live-read to opt-in, and my P-B forbids live-read on the *guarantee* path. Lock it jointly: **graduation into `.orchestrator/` is the default and the only thing the deterministic floor reads; live-read is a configured recall *booster* that never replaces the raw-file grep** — the exact shape we both gave embeddings in DQ-2. This makes our two positions one rule.

- **[round-trip-AC-green-on-a-store-no-alarm-watches]** — *activation-loop claims* (Rec 2 risk, L69; `[round-trip-half-deferred]` L31): without G-1 in P0, AC-1/AC-6 pass "only on a hand-promoted project," so the round-trip test is misleadingly green. *pipeline-reliability claims* (my review Rec 3 `[lock-regressions-at-fixture-byte-equality]`, L71): AC §5 items are specified *behaviorally* ("confirms the entry resolves," "rebuilds successfully"), not at fixture-byte-equality — a behavioral round-trip assertion can pass while drifting. *Why dangerous (combined):* activation-loop wants AC-1 to be *meaningfully* green on a default project; I want AC-1 to be *byte-stably* green. If we ship AC-1 as a behavioral "resolves in an inject" check, it can be green on a default project AND still drifting — the worst case is a round-trip test everyone trusts that silently stops asserting the column order it was built to lock (the very B-3 defect). *Suggested cooperative resolution:* merge the two asks into one AC: the round-trip oracle (a) runs on a *default-intensity* fixture project (activation-loop's coverage demand) AND (b) asserts the injected payload **byte-for-byte** against a committed expected file (my determinism demand). One fixture, both guarantees.

### Tensions

- **[capture-by-default-at-Quick vs Context-Minimization]** — *their position:* FR-8/G-1 — always run `append-decision.sh` for explicit decisions even at Quick, and auto-graduate notes (Rec 2/8, L64-69/106-111), so the default intensity stops writing nothing. *my position:* I'm fully supportive of *capture* at Quick, but my domain's concern is the *inject* side — every byte graduated into `.orchestrator/` is a byte the dispatch payload may carry, and an unscoped auto-graduate (activation-loop itself flags this in Rec 8 `[auto-graduate-mechanism-thin]`) pollutes the store the grep fallback sweeps, degrading *every* subsequent inject's signal-to-noise. *nature of tension:* productive — capture-completeness vs payload-minimization, the same axis Constitution Principle I governs. *coordination needed:* adopt activation-loop's own Rec 8 fix (a `decision:`-tagged note shape, fired at phase-close, not continuously) as the *shared* qualification rule — it satisfies their capture-at-Quick ask while keeping my fallback corpus clean. We jointly recommend: capture explicit decisions at Quick always; auto-graduate only structured/tagged notes at consolidate boundary.

- **[new capture command surface vs minimal pipeline fixes]** — *their position:* Rec 5 `[specify-FR-7-capture-command]` (L85-91) — resolve DQ-7 toward a **new first-class command** (`orchestrator:note`), which owns classification + confirmation. *my position:* my P0 is deliberately surface-minimal — fix the five proven bugs, add the alarm, enumerate the fallback; a net-new command is build-shaped, not hotfix-shaped. *nature of tension:* blast-radius / phasing, not disagreement on value. A new command is a discoverable verb (their correct point) but also new install-surface, new docs, new runtime-parity obligations. *coordination needed:* agree the *confirmation mechanism* activation-loop wants the command to own — "a `build-context.sh` round-trip assertion that the just-written entry resolves" — is exactly my fail-loud inject-provenance check (FR-5c / FR-15) wearing a different hat. Build the **mechanism** in P0 (it's the alarm), expose the **command** in P1. The command then *composes* the P0 primitive rather than re-deriving it.

- **[foreground-BUG-A-as-source-of-truth-failure vs rebuild-bug-as-headliner]** — *their position:* Rec 1 `[promote-BUG-A-to-P0-co-primary]` (L57-63) — BUG A (B-3 format mismatch) is the *source-of-truth* failure and should be co-primary, above the rebuild bug which is "only" a cache failure. *my position:* I agree B-3 is source-of-truth-grade, but I'd note the *rebuild* abort (B-1) is also more than a cache failure in practice — when the rebuild aborts, the raw corpus is fine but *no* index exists, which is precisely when the index-free grep guarantee must carry the load. *nature of tension:* emphasis/taxonomy — which proven bug is "worst." *coordination needed:* none adversarial; we reinforce. Resolution: rank by *which-store-is-unreadable* — B-3 makes the **raw store** unreadable (worst, agree with activation-loop), B-1 makes the **index** absent (recoverable *only because* my index-free fallback exists). State both in §8 with that distinction; activation-loop's co-primary framing for B-3 stands, and it strengthens my case that the index-free path is non-negotiable.

- **[round-trip-test against the consumer's awk field indices]** — *their position:* AC-1 is "the producer-and-consumer-are-one-contract test" and DQ-6 reconciles producer vs consumer column order (review L19, Rec 3 L71-77). *my position:* (my Off-Base `[B-3 line-numbers]`, L59) — DQ-6 must reconcile *three* artifacts, not two: producer format, the consumer's *comment* (`scope-filter.sh:351` says `4=Scope,5=When`), and the consumer's *actual awk* (`:353-354` reads `$5`/`$6` because the leading pipe shifts every column). *nature of tension:* activation-loop's round-trip framing is correct but under-specified against the live awk reality. *coordination needed:* the round-trip oracle (their AC-1) must be authored against the **observed awk field indices**, and DQ-6's winner must re-align producer + init header + consumer comment + consumer awk in one change set — extending activation-loop's own Rec 9 `[surface-init-header-as-discrete-item]` from three call sites to four.
