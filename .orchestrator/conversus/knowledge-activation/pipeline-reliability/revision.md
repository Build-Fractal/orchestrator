### Recommendation Dispositions

#### Recommendation 1: mandate-index-free-fallback-for-all-consumers (P0)
- **Original position:** Produce a checked-in consumer inventory (every reader of `KNOWLEDGE-INDEX.md` / `knowledge.db` / `resolve-entries.sh`) and require the deterministic-grep-over-raw-files fallback + provenance header for *each*, with a regression that deletes BOTH index and db and asserts every consumer still returns scoped hits.
- **Disposition:** Modified.
- **Explanation:** Two cross-reviews bend this in the same direction without killing it. **framework-steward** (Dangerous Contradictions `[grep-everywhere default-on vs token-budget governance]`) is correct that "grep over raw files on every consumer, P0, no budget governor named" is an *ungoverned content firehose* — fail-loud traded for fail-loud-and-oversized, blowing the M031-right-sized Quick profile and violating Principle I. **activation-loop** (Dangerous Contradictions `[index-free guarantee over an empty store]`) is correct that an enumerated, byte-locked grep fallback running over a *mis-columned (B-3) or never-written (G-1)* store still injects nothing — "a trust receipt that certifies an empty/unparseable corpus as 'activated.'" New concrete version, splitting the recommendation into a P0 floor and a governed retrieval: **(a)** the *consumer inventory + fail-loud + provenance header* ships P0 on all consumers (cheap, no content firehose) — this is the part framework-steward and I agree on as the safe P0 minimum; **(b)** the *grep retrieval itself* ships P0 but **budget-bounded through the existing M036a token-budget governor (SC-3/SC-7)** — the regression asserts "hits returned with index+db deleted, *within budget*," not unbounded; **(c)** the consumer inventory must include the **negative finding** activation-loop demands — "runtime agent memory (G-3) is a store with zero readers" — so the enumeration surfaces the two-store divergence rather than enumerating only already-wired stores; and **(d)** the byte-equality fixture corpus for the fallback must assert over rows produced by the *unified* producer (FR-1/B-3 resolved first), so one corpus locks both capture-format and grep-fallback — neither ships green alone.

#### Recommendation 2: scope-the-unguarded-command-audit-to-an-artifact (P0)
- **Original position:** Emit a committed audit artifact enumerating *every* pipeline in `rebuild-index.sh` + sourced libs, classified guarded/unguarded, each unguarded one *fixed or justified*, with an AC that the artifact lists zero unjustified-unguarded pipelines.
- **Disposition:** Modified.
- **Explanation:** **framework-steward** (Dangerous Contradictions `[P0 blast-radius — "audit ALL unguarded set -e/pipefail" as a P0 deliverable]`) lands a real hit: "audit every pipeline, fix or justify each" can balloon a one-line `:117` guard into a multi-file refactor across `lib/index-utils.sh` / `lib/graph-db.sh`, making the proven-bug ship date hostage to auditing pipelines with no reproduced defect — the Principle XV Surgical Precision violation. My original already bounded *scope* to "`rebuild-index.sh` + its direct `source`d libs only," but it conflated *enumeration* with *fixing*. New concrete version, adopting framework-steward's bisection: the audit is a **grep-enumeration** (cheap, deterministic, mechanical) of every pipeline in `rebuild-index.sh` + its directly-sourced libs, classified guarded/unguarded — **enumerate-and-classify ships P0**. **Fixing** a non-`:117` unguarded pipeline ships P0 *only if it has a reproduced failure*; otherwise it lands as a *justified-and-tracked row* in the artifact, not a P0 code change. The AC becomes "the artifact exists, enumerates all pipelines, and every unguarded one is either fixed (if reproduced) or carries a justification" — closing the "guard assumed, never enumerated" trap *without* the open-ended refactor.

#### Recommendation 3: lock-regressions-at-fixture-byte-equality (P0)
- **Original position:** Each P0 regression ships a committed fixture corpus + exact expected-output file asserted byte-for-byte (the `INDEXED:/SKIPPED:` summary, the degraded-payload provenance header block, the freshness-flag output).
- **Disposition:** Modified.
- **Explanation:** This survives as the discipline but takes two sequencing corrections. **framework-steward** (Dangerous Contradictions `[fixture-byte-equality regressions as P0 across all surfaces]`) flags an ordering hazard I created against *my own Rec 4*: you cannot byte-lock the provenance-header output when its schema is still open (my Rec 4 defers the schema to P1). **activation-loop** (Dangerous Contradictions `[fixture-byte-equality for grep vs round-trip non-determinism]`) flags that a *static* frozen-corpus fixture collides with a *round-trip* test that writes a fresh entry at runtime — the frozen expected-output can't contain the dynamically-appended row. New concrete version: split the harness into **(a)** static byte-equality fixtures shipping P0 for the *deterministic, schema-settled* surfaces — the `INDEXED:/SKIPPED:` summary line, the path-collision index count, the freshness flag; **(b)** the *provenance-header* byte-fixture ships *with* its schema (my Rec 4, P1), so byte-lock and contract land together; **(c)** a separate *round-trip oracle* (activation-loop's AC-1 lane) that writes → rebuilds → greps → asserts the written entry is present dynamically — same determinism discipline (`LC_ALL=C`, no wall-clock), different assertion shape. Don't force the round-trip into a frozen-corpus fixture. The byte-equality *default* is undiminished; only the per-surface timing is corrected.

#### Recommendation 4: pin-the-provenance-header-as-a-versioned-byte-contract (P1)
- **Original position:** Define an exact line/block with fixed key order, `source:` enum `{index,grep-fallback,degraded}`, `index_age`, `entries_considered`, a `schema_version`; lock with a fixture; document where M034/M038/wiki consumers read it.
- **Disposition:** Modified.
- **Explanation:** Survives as a P1 contract but gains two design constraints from cross-review. **framework-steward** (Tensions `[how loud is "loud" — provenance header tokens vs Context Minimization]`) is right that every field on *every* inject is a standing Principle-I token cost: the *payload-resident* header should be **minimal** (source enum + one age/count field), with the richer fields (`entries_considered`, `schema_version`) emitted to stderr / the evidence artifact rather than the always-injected line. **activation-loop** (Tensions `[byte-stable provenance header schema vs round-trip confirmation reuse]`) is right that the header has a *second* consumer — the capture-confirm step needs to assert "did *this specific* just-written entry appear?" — so the schema must be designed with both downstream parsers and the synchronous capture-confirm at the table, adding a resolved-id surface the confirm-step can assert against, versioned so M034/M038 ignore it gracefully. New version: **minimal payload header + full schema in stderr/evidence-artifact + a resolved-id field the capture-confirm reuses**, one design pass, two consumers.

#### Recommendation 5: resolve DQ-1 — demote the index to cache, with an index-free path on EVERY consumer (P0)
- **Original position:** Adopt "cache, may be absent"; reject the hard-freshness-gate alternative because a gate that *blocks* dispatch on a stale index reintroduces a single point of failure for whether context is considered at all.
- **Disposition:** Surviving.
- **Explanation:** Both cross-reviews converge here with no dissent. **framework-steward** (Safe Agreements `[index-as-cache / P-B is constitution-grounded, not novel]`) grounds the demotion in Principle XI three-temperature storage and states "DQ-1 should resolve 'demote' jointly." **activation-loop** (Tensions `[which silent failure is more damaging]`) notes my own P-B framing *logically concedes* that a truth-layer bug outranks a cache-layer bug — which reinforces, not undercuts, the demotion. The "every consumer" clause is implemented via Rec 1 (now budget-bounded), but the *architectural stance* — index is cache, demote it — stands unchanged.

#### Recommendation 6: resolve DQ-2 — deterministic grep is the floor; embeddings only additive (P1)

- **Disposition:** Surviving (strengthened to a resolved invariant).
- **Explanation:** Unanimous across all three reviewers. **framework-steward** (Safe Agreements `[determinism over embeddings is the activation guarantee]`) reaches the identical invariant from Principle IX and adds my own nondeterminism-vector guards (`LC_ALL=C`, no wall-clock fields, stable file ordering). **activation-loop** (Safe Agreements `[grep-floor is the guarantee; embeddings only additive]`) reaches it from the round-trip's immediate-resolve confirmation needing deterministic same-instant retrieval. My cross-review of framework-steward (Dangerous Contradictions #3) explicitly flagged the *only* residual risk: a naive synthesis could mislabel framework-steward's Principle-IX framing and my reproducibility framing as a *fork*, leaving DQ-2 falsely "open." Disposition adjustment: **DQ-2 should be recorded as jointly RESOLVED in the brief, not carried as an open question** — deterministic grep is the guarantee floor and the sole input to the corpus-gate evidence artifact; embeddings, if ever added, are additive recall that never gates and never enters the receipt.

#### Recommendation 7: resolve DQ-3 — rebuild-then-warn-if-still-bad; never auto-rebuild silently mid-dispatch (P1)

#### Recommendation 8: resolve DQ-4 — header always + stderr always; hard gate only on highest-stakes paths (P0)

### New Recommendations

**[budget-bound every grep-fallback path through the M036a governor]** (Priority P0) — *Triggered by* framework-steward (Dangerous Contradictions `[grep-everywhere default-on vs token-budget governance]`). *Proposed change:* every index-free grep-over-raw-files retrieval path declares its token budget through the existing M036a token-budget governor (SC-3/SC-7); the "fallback survives index+db deletion" regression asserts hits returned *within budget*. *Scope boundary:* reuses an existing governor — no new budgeting machinery; applies to the retrieval side of FR-5/FR-12/FR-14 only. *Rationale:* a fail-loud fix with no budget governor trades a silent under-load for a silent over-load — both Principle I violations; the failure mode is a degraded inject that is now *loud and oversized*, re-inflating the Quick profile M031 deliberately right-sized. **[surface G-3 as the named negative finding in the consumer inventory]** (Priority P0) — *Triggered by* activation-loop (Tensions `[enumerate-every-consumer vs the consumer that doesn't read at all]`). *Proposed change:* the Rec-1 consumer inventory explicitly records "runtime agent memory is a store with **zero** readers" as a first-class enumerated row, not an omission. *Scope boundary:* documentation/inventory artifact only — the *fix* (G-3 graduation, FR-9) stays P1; only the *surfacing* is P0. *Rationale:* my horizontal enumeration (all readers of the known stores) is blind to a *whole store the readers can't see*; without naming it, the inventory enumerates only already-wired stores and the two-store divergence stays invisible during the very fix window meant to make degradation loud.

### Scope Discipline

**What I removed.** I dropped the open-ended "fix or justify *every* unguarded pipeline" framing from Rec 2 (now: enumerate-all P0, fix-only-the-reproduced P0, justify-and-track the rest). I trimmed "header always" to "*minimal* header always in payload, full provenance in stderr" (Recs 4, 8). I folded my standalone no-vestigial-index doctor check into the existing consolidated doctor surface rather than minting a new one (Rec 10).

**What new scope I still ask for, and why.** I added one genuinely new P0 constraint — *budget-bounding* the grep fallback through the M036a governor — because without it the all-consumers coverage I insist on becomes an ungoverned firehose. This is not scope creep; it is the guardrail that makes my existing ask shippable. I also expanded P0 *membership* (FR-6 + explicit-capture half of FR-8) — this is concession to activation-loop, not expansion of my own lane.

**Concession on activation-loop's central point (capture-format + capture-by-default in P0).** **Yes — I concede it.** A resilient, byte-equality-locked, index-free grep rebuild over a *mis-columned (B-3)* or *never-written (G-1)* store still injects nothing useful: grep finds the row but `filter_decisions` extracts scope from the wrong awk field and the scope-match drops it, or there is no row to find at all. My own P-B principle — "the index is a cache, the raw corpus is truth" — *logically concedes* that a truth-layer (capture-format / capture-existence) failure outranks a cache-layer (rebuild/index) failure, because P-B explicitly permits the cache to be absent. Therefore **FR-1 (B-3 round-trip parser unification) must be sequenced as a prerequisite of my index-free fixture suite**, and **FR-6 + the explicit-decision-capture half of FR-8 must ship in P0 alongside pipeline hardening**, so the loud 0-MEM alarm (FR-15) points at a populated store rather than certifying an empty one as "activated." One fixture corpus locks both capture-format and grep-fallback; neither ships green alone. My standing caveat: the *alarm* (FR-15 + provenance) is the substrate that makes *every* P0 fix — including the capture items — verifiable, so within P0 the alarm has no dependencies and the capture items are load-bearing tenants; both are P0, the list is unordered.

**Concession on framework-steward's blast-radius point (bound the unguarded-command audit).** **Yes — I concede it.** An unbounded "audit ALL unguarded `set -e`/`pipefail` and fix each" can balloon a one-line `:117` guard into a multi-file refactor across sourced libs, making the proven-bug ship date hostage to pipelines with no reproduced defect — the Principle XV violation framework-steward correctly names. The audit is bounded to `rebuild-index.sh` + its *directly sourced* libs only, is a cheap grep-enumeration (not a per-pipeline refactor), and *fixing* a non-`:117` pipeline is P0 only when a failure is reproduced — otherwise it is a justified-and-tracked row. This satisfies the "guard was assumed, never enumerated" closure *and* Surgical Precision simultaneously.

**What remains fixed.** The fail-loud thesis (P-A), index-as-cache (P-B/DQ-1 demote), deterministic-grep-floor (DQ-2, now resolved not open), the provenance header traveling in the payload, the byte-equality testing *default*, content-hash as the freshness *signal*, and §7's milestone-independent P0 *structure* — all survive unchanged in principle. The corrections are to *granularity, sequencing, and budget governance*, not to the load-bearing invariants.

### Position Summary

Of eleven original recommendations: **zero withdrawn, seven modified (Recs 1, 2, 3, 4, 8, 10, 11), four maintained (Recs 5, 6, 7, 9)**, plus two new recommendations surfaced by cross-review. Nothing was withdrawn because the cross-reviews were cooperative and convergent — both other agents independently re-verified my B-1/B-2/B-3 live-source citations and accepted the defects as real; the pushback was uniformly about *scope, sequencing, and governance*, not correctness. DQ-2 additionally moves from "open" to "jointly resolved" given unanimous agreement, which I flag specifically so synthesis does not mislabel two convergent framings as a fork.

The most significant change in my thinking is the concession to activation-loop that **a perfectly hardened retrieval pipeline over a broken capture format or an empty store injects nothing** — and that this follows directly from my *own* P-B principle, which permits the cache to be absent and therefore ranks a truth-layer failure (capture) above a cache-layer failure (rebuild/index). I came in leading with the rebuild-bug story as P0-primary; I now hold that B-3 (capture-format) and the capture-by-default items (FR-1, FR-6, explicit-FR-8) are co-primary P0 alongside my pipeline fixes, and that one fixture corpus must lock both. The second-largest shift is conceding framework-steward's blast-radius bound: my audit and my all-consumers fallback both needed *governors* (a scope bound on the audit; the M036a token budget on the grep fallback) to be shippable under hotfix urgency rather than becoming the very over-scope they were meant to prevent.

My remaining highest-priority recommendation is unchanged in spirit but sharpened: **the index-free deterministic-grep fallback must be a mandated, enumerated, fixture-byte-equality-tested invariant for every index consumer — now budget-bounded through the M036a governor, with the consumer inventory explicitly naming runtime agent memory as a zero-reader store, and asserted over rows produced by the unified (FR-1-fixed) producer.** A fail-loud guarantee covering 1-of-N readers is a silent fail-open for the other N-1; and a fail-loud guarantee over an unparseable store is a green receipt for an empty corpus. Both holes close with the same one-corpus, budget-bounded, all-consumers fixture suite.
