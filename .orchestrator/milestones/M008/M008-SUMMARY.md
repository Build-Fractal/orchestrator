M008 transformed the orchestrator from a spec-kit extension into a standalone multi-runtime extension with adaptive process intensity. Across 7 phases (P01-P07), delivered: (1) Adaptive Intensity Engine — analyzes task descriptions along scope/risk/complexity axes and recommends Quick/Standard/Full intensity with environment capability awareness. (2) Backend-Agnostic Dispatch Interface — uniform entry point with filename-based adapter routing, two local backends (Claude Code Agent tool + Codex CLI SDK), structured result/error schemas with distinct exit codes. The explicit seam for M010's cloud backends. (3) Intensity-Aware Pipeline Scaling — central 7×3 stage×intensity matrix wires intensity awareness into every pipeline stage (discuss, research, plan-phase, dispatch, verify, knowledge, auto) with atomic mid-workflow override. (4) State & Namespace Independence — 5-rule root resolver, unified config, hard migration tool, surgical derive-phase refactor, namespace aliases. Full workflow runs standalone without spec-kit (SC-004 validated). (5) Runtime & Format Adapters — auto-detection + 3 runtime adapters (claude-code/codex/cursor) with HOME/project-dir guards + 2 format adapters (native round-trip, spec-kit one-directional read). (6) Multi-Runtime Packaging — open-standard SKILL.md format, 12 skills generated from commands, installable bundle, 3 runtime installers delegating to adapters, offline-safe version checker. (7) Init, Onboarding & Spec-Kit Bridge — orchestrator:init detects project (10 languages + 9 frameworks + 6 CI systems + 9 tools), generates config + runtime-appropriate instruction file (CLAUDE.md/AGENTS.md/.cursor/rules), installs skills. Reinit preserves user-edited custom blocks via comment markers. Full onboarding completes in ~1 second wall-clock (SC-005 validated with 2 orders of magnitude margin vs 5min target). Cross-cutting patterns: hermetic-first testing (mktemp fixtures, never touch real HOME), comment-aware Bash 3.2 compat, filename-based auto-discovery mirrored from P02 through P05/P06, thin delegation pattern, user-edit preservation via comment-delimited blocks. M008 is the foundation for M009 (debug protocols) and M010 (cloud dispatch via Managed Agents).
