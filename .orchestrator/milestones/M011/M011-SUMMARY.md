M011 (Spec Management) delivers the "paste a spec, get a roadmap" value proposition end-to-end. Seven phases took the orchestrator from an opaque-spec-file consumer to a full ingest→chunk→scope-filter→normalize→fidelity-gate pipeline that treats specs as structured knowledge on equal footing with the existing three-temperature knowledge model (M002/M007). P01–P03 built the deterministic chunker (spec directory tree with six subcategories, SPEC-prefixed natural IDs, nested-directory indexing, create-entry.sh SPEC- namespace support, full markdown→chunk classifier with classify+dispatch decision layer, versioned-ID supersession chains, REMOVED detection, phase-impact REVIEW emission). P04 wired scope-filter.sh to resolve `spec/*` scope tags (graph-mode + spec-scope-tags mode), letting build-context.sh deliver scope-filtered spec chunks in dispatch payloads per Constitution Principle I. P05 wired chunks-first evaluation and intensity-aware roadmap generation into commands/evaluate.md and commands/roadmap.md (spec-metrics.sh counts non-superseded chunks; spec-story-graph.sh emits directional story-to-story depends_on edges via bidirectional-traverse + directional-frontmatter-filter composition; intensity-gate.sh roadmap stage with Quick/Standard/Full modes). P06 delivered the user-facing commands/ingest.md, four doc-shape verify scripts, a full sandbox E2E gate script, a timing harness (<60s on representative specs), and dogfood evidence against specs/016-autonomous-hardening/spec.md (20 chunks, 7s elapsed). P07 closed with format-agnostic intake and a reusable Conversus fidelity gate: detect-spec-shape.sh probe classifier, normalize-spec.sh thin wrapper dispatching through dispatch-interface.sh (no hardcoded LLM calls), templates/spec-normalizer-prompt.md, a reusable Conversus adapter (scripts/dispatch/adapters/tool/conversus.sh with check/gate/parse-verdict subcommands, graceful degradation, CONVERSUS_STUB escape, three-value exit contract 0/1/2), commands/conversus-gate.md designed for M013/M014 reuse with different presets, templates/conversus-presets/normalize-fidelity.yml, templates/gate-result.md, and integration into commands/ingest.md as a pre-chunker 6-step pipeline (detect-shape → normalize → resolve-policy → fidelity-gate → chunker → rebuild) gated by a new `ingest` intensity stage (Quick=normalize; Standard/Full=normalize+fidelity-gate). A 222-line user guide (docs/ingesting-arbitrary-specs.md) covers flag semantics, BLOCK resolution, stub modes, and preset extension.

Cross-cutting verification: 45+ `m011-*.sh` verify scripts created across the seven phases, plus preserve-references regressions that guard the growing doc surface phase-over-phase. Final milestone validator passes 121/121. P04 regression stays green across all downstream phase additions. Bash 3.2 compat is scanned in every phase. E2E timings stay well under contract (<60s ingest, <120s foreign PRD pipeline in stub mode).

Cross-cutting patterns established: decision-layer wrapper around creation primitives (P03); chain-walking next-version supersession (P03); intensity-gate stage registration via minimal case-row insertion (P05, P07); chunks-first with raw-spec fallback in command docs (P05); bidirectional-traverse + directional-frontmatter-filter for typed edges over generic graphs (P05); `grep -Fq -- "$tok"` end-of-options idiom for --flag-shaped tokens under BSD grep (P06); sandboxed PROJECT_ROOT=$(mktemp -d) + EXIT-trap for pipeline tests (P06, P07); evidence-present token gate (file-exists + token-contains) as standard dogfood verification shape (P06, P07); per-phase preserve-references regression contract (P06, P07); `_STUB=1` env-var escape hatches as first-class deterministic-testing contracts (P07 NORMALIZER_STUB + CONVERSUS_STUB); three-value exit contract (0/1/2) for gate-shaped commands where BLOCK is distinct from error (P07); dispatch-interface.sh as uniform LLM-agent-dispatch boundary (no bash HTTP calls, P07).

Architectural decision closed: D004 — Conversus integration lands inside M011/P07 as a reusable adapter, not as standalone M017. M013/M014 can now invoke the same adapter with their own preset and target-shape inputs at opt-in gate points, without rebuilding Conversus infrastructure.

Next up per the revised forward roadmap: M019 Tier-1 metrics emitter ships first as the kickoff unit after M011 closes, so M012–M014 dogfooding produces measured data on time/tokens/$/quality across task/phase/milestone/project granularities.
