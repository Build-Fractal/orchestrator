T02 delivered the reusable Conversus tool-adapter and its three companion artifacts (command doc, preset, gate-result template) plus two stub fixtures and four per-artifact verify scripts. All ten artifacts are pure-additive; no pre-existing adapter, command, template, or fixture was modified. The adapter lives under a new sibling subdirectory scripts/dispatch/adapters/tool/ (peer of backend/, format/, runtime/) per MEM018 filename-routed auto-discovery; the preset template lives under a new sibling templates/conversus-presets/ so future milestones (M013, M014) can drop in new presets without adapter changes (roadmap directive: adapter not one-shot gate). The adapter is strictly an external-tool bridge — it calls the conversus binary, parses the gate-result.md artifact, and reports a verdict. No agent prompts or deliberation logic live in bash; all two-agent reasoning is authored in templates/conversus-presets/normalize-fidelity.yml and executed by conversus itself. Resolver order: CONVERSUS_STUB=1 (test stub) > command -v conversus (PATH) > CONVERSUS_HOME/bin/conversus > HOME/Sites/conversus/bin/conversus. Graceful degradation: when the binary is missing, gate emits a SKIPPED: line and exits 0 so the calling pipeline can proceed without a gate. Exit-code contract: 0=PASS or SKIPPED, 2=BLOCK, 1=adapter error (3-value so callers can distinguish a valid blocking verdict from an operational failure). Stub mode copies tests/fixtures/gate-result-pass.md or gate-result-block.md into the output path (selected by CONVERSUS_STUB_VERDICT, default PASS) for deterministic testing. Verification: 4/4 m011-p07-conversus-* verify scripts PASS (adapter-shape 18/18, doc-structure 17/17, preset 8/8, gate-result-template 13/13). The adapter-shape script exercises the stub-mode end-to-end path (parse-verdict on pass+block fixtures; gate stub-mode PASS exits 0, BLOCK exits 2). No deviations from the task plan.
