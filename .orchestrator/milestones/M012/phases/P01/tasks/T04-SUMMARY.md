Shipped scripts/wiki/wiki-generate-nav.sh — the MkDocs nav block generator. Reads wiki-scan-sources.sh output once, emits a stream-friendly YAML nav block, and splices it into wiki/mkdocs.yml between "# >>> M012-P01 nav (auto-generated — do not edit by hand)" and "# <<< M012-P01 nav end" marker comments via an awk-driven state machine + atomic mv. Bash 3.2 compliant (no declare -A, no mapfile, no process substitution, no ${var^^}); MEM004 carve-out used for pipes/awk/$() inside the script. Supports --dry-run (prints block to stdout; no file writes) and --root PROJECT_ROOT; --help prints header. On first run, markers are appended at EOF of wiki/mkdocs.yml with an empty body, then awk splits pre/post and the freshly assembled body replaces the middle. Atomic write goes through a same-directory staged file (.mkdocs.yml.staged.$$) + mv so partial writes are impossible. Top-level nav order (fixed per must-have): Home, Constitution, Decisions, Knowledge, Milestone Summary, Milestones. Archive group is emitted only when the scanner yields archive:M### records (current .orchestrator/archive/ holds only handoffs/ — no archived milestones — so Archive is correctly absent in the current dogfood output; the orphan-free / "every leaf points at a stub" must-have forbids emitting Archive with a non-existent archive/index.md stub). Nav title derivation follows payload step 6: M### milestone group label is the raw id; M###-*.md strips prefix and title-cases tail ("M011-CONTEXT.md" -> "Context"); P##-*.md similarly ("P01-PLAN.md" -> "Plan"); T##-*.md keeps task id + title-cased kind ("T01-SUMMARY.md" -> "T01 Summary"); section-index pages use "Overview". Bucketing awk passes cover four shapes per milestone/phase: milestone-top (no further slashes after MID/), phase-top (no further slashes after PID/), task-level (tasks/ prefix), and catch-all "extras" — records deeper than the canonical phase/tasks structure (e.g. milestones/M004/phases/P05/fixtures/*.md, milestones/M008/archive/P01/*.md). Extras emit flat leaves under their owning phase (phase-extras) or milestone (milestone-extras) with a slash-joined label derived from the tail path so every scanner record gets a nav entry. Dogfood run against current .orchestrator/: 947 scanner records -> 1030 unique nav leaves (947 artifact leaves + 83 auto-generated Overview leaves: 1 milestones + 13 M### + 68 phase + 1 Home). Every nav leaf target verified to exist as a stub under wiki/docs/ (0 missing). Idempotency proven by shasum diff across two consecutive runs (identical) and by dry-run diff across two runs (identical). Nav block is 1115 lines; wiki/mkdocs.yml preserves all original base config (site_name, theme, plugins, markdown_extensions) unchanged above the start marker. No copied or symlinked artifact appears — every leaf points at a wiki/docs/ stub that resolves back to .orchestrator/ via the include-markdown plugin (AD-3 SSOT preserved). No verify scripts written; those belong to T05. mkdocs is not on PATH locally so strict-build smoke check deferred to T05 m012-p01-serve-smoke.sh.
