T01 lands the production code for the M018/P04 head-drop tier — the boundary-refusing line-aligned snip that head-drops over-budget section bodies in the dispatch-time payload while preserving the trailing 30% byte-identical. The implementation is a single inline awk pass inside _bc_apply_tier2 in build-context.sh, placed adjacent to _bc_apply_tier1 per the dispatch-internal helper convention (MEM004 carve-out): same shape, same defaults-via-accessor contract, same TMPDIR_BUILD/_tier2_stats.txt/_tier2_violations.txt side-effect file pattern, same atomic mv on rewrite. The awk does the heavy lifting because shell-shape rules (AP-009) ban compound chains > 2 and $(...|...) — the awk-internal pipeline is exempt because it is awk-internal, not shell-shape.

The load-bearing inner loop is the boundary-refusal detector: each body line carries a body_unsafe[i] flag computed at the START of the line (before span-state update) — true when the line sits inside an open ^---$ frontmatter pair or an open ^`{3,}[a-zA-Z0-9_-]$ code-fence (closed only on a matching backtick-count line per MIT-01). The cut walker computes the naive cut byte (floor(body_chars * (1-ratio))) then retreats DOWN line-by-line until it finds a body_unsafe[j]==0 line; if it reaches line 0 without finding one, the section passes through unmodified plus a tier_preservation_violation JSONL emit (tier=tier2, pattern=spanning-vocabulary-label). Direct awk-pipeline fixture exercise (small budget=500 tokens against a synthetic 14 kB Knowledge body) emits the marker, drops 7 leading lines above a 4-backtick fence, and preserves both the opening and closing 4-tick fences plus the inner 3-tick line that does NOT close the outer fence (MIT-01 verified live).

Three new config keys land under compression.tier2.* in both .orchestrator/config.yml and templates/orchestrator-config-default.yml: enabled (true), section_budget_tokens (1500), protected_tail_ratio (0.3). Three matching kf_get_tier2_* accessors land in scripts/lib/knowledge-filter.sh mirroring the kf_get_tier1_* pattern verbatim. kf_read_compression_scalar gains an in_t2 sub-block tracker alongside the existing in_kf / in_up / in_t1 — additive change, all four pre-existing accessors remain byte-identical in behavior. The payload_breakdown JSONL emitter gains the additive integer tier2_savings_tokens field per CON-5 (pre-T2 records remain valid JSON; rollups treat missing as 0).

Disable contracts: COMPRESSION_ENABLED!=true OR TIER2_ENABLED!=true short-circuits before any payload mutation. Self-test confirms ORCH_OVERRIDE_COMPRESSION_ENABLED=false produces a payload byte-identical to the enabled run (108736 bytes both — Tier 2 emits no marker on the live dispatch payload because the assembler splits on inner ## subheadings inside knowledge entries, which keeps the per-section body bodies under the 1500-token budget; T02's controlled fixtures will exercise the over-budget path). Body-level pres_check_section ... tier2 runs over the rewritten payload as a whole; failure restores pre-snip bytes byte-identical and emits tier_preservation_violation. T01 ships ONLY the production code; T02 ships the seven private verifiers, the two over-budget fixtures (one with a 4-backtick fence to exercise the boundary-refusal path), the fixture-staging helper, the P04-SUMMARY, and the CLAUDE.md / AGENTS.md recent-changes refresh.
