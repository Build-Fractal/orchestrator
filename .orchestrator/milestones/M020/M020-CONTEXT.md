## Architectural Decisions

### AD-1 — Query-surface shape [agent-default — operator review required]

**Question** (spec-driven, from FR-2): how does the dispatch-callable query surface resolve `topic=<X>`? Exact-match only, semantic, or hybrid?

**Agent default**: **Exact-match + topic-keyword-index** for M020/P01 scope. Semantic/hybrid resolution is deferred unless M024 routing demonstrates real need. Source: spec 025 FR-2 (updated during clarify-weave), CON-3, A-3. Consistent with Principle XIV (No Speculative Complexity) — no semantic infrastructure without evidence that exact-match fails.

### AD-2 — Query-index lifecycle [agent-default — operator review required]

**Question**: is the topic-keyword-index ephemeral (rebuilt on every query) or persisted (rebuilt at consolidate-time and cached to disk)?

**Agent default**: **Rebuilt lazily on every query**, no persisted cache, at M020/P01. Principle VI (State On Disk Is Truth) argues against a stale-cache failure mode for v1; rebuild cost is tolerable against the current knowledge-tree size (~25–50 entries per milestone). Revisit if M019 Tier 1 metrics show rebuild latency blocking dispatch context-assembly. Source: inferred from spec 025 FR-8 + FR-9 (read-only, file-on-disk), D016 sequencing (M019 Tier 2+3 lands after M020).

### AD-3 — Cluster ID scheme [agent-default — operator review required]

**Question**: how are cluster IDs generated by the Jaccard clustering step (spec FR-5)?

**Agent default**: **Content-hash of the cluster's sorted member-ID set**, truncated to 8 hex chars and prefixed `C`. Deterministic (same members → same ID across runs), human-legible, collision-resistant at milestone scale. Avoids stateful counters that complicate concurrent consolidate runs. Source: inferred from spec 025 FR-5 + CON-5; no specific D-row authority.

### AD-4 — Schema migration model [agent-default — operator review required]

**Question**: spec 025 FR-10 commits to incremental migration ("status: graduated on next touch"). What exactly is a "touch"?

**Agent default**: **A touch is any write operation through `graduate.sh` or `orchestrator:consolidate`**. Read operations via the query surface do NOT touch; they infer `status: graduated` in-memory for pre-M020 entries per FR-10 but leave the file unchanged. The write-back happens only when the operator explicitly acts on the entry. Source: spec 025 FR-8 + FR-10 + NG-3.

### AD-5 — Preferences file format [agent-default — operator review required]

**Question**: spec 025 FR-6 names `~/.orchestrator/preferences.yml` + `.orchestrator/preferences.yml`. YAML parsing strategy?

**Agent default**: **Scalar-only YAML parsed via a shell helper (grep/sed-based), not a full YAML parser**. Preferences are flat key-value with scalar values (float threshold, int cluster-size, string state-filter) — flat-scalar grep is sufficient and keeps M020 dependency-free. If preference shape later evolves to nested structures, switch to `yq` or equivalent via a D-row. Source: inferred from spec 025 FR-6 (scalar values only in examples); Principle XIV (no speculative complexity).

### AD-6 — decision_history storage format [agent-default — operator review required]

**Question**: spec 025 FR-7 commits to append-only decision history per entry. Stored as YAML list in frontmatter? Separate file?

**Agent default**: **YAML list under the `decision_history:` frontmatter key, each entry a flow-style map**: `{ts: "2026-04-23T00:00:00Z", rationale: "...", operator: "<email>", cluster_id: "C<hash>"}`. Frontmatter is the entry's SSOT (Principle VI); a sibling file would introduce two-file-consistency failure modes. Cap per-entry history growth by length, not by compaction (compaction deferred per NG-6). Source: spec 025 FR-7, NG-6.

### AD-7 — Query-surface implementation language [agent-default — operator review required]

**Question**: spec 025 FR-2 is silent on whether the query surface is bash or a higher-level language.

**Agent default**: **Bash/POSIX sh, matching the rest of the orchestrator's script layer**. Consistent with `scripts/**` conventions (CLAUDE.md Active Technologies); keeps M020 runtime-agnostic. Grep + awk + jq (if jq is available) are the canonical tools. Source: inferred from project conventions (CLAUDE.md Active Technologies).

## Design Constraints

### DC-1 — Principle I (Context Minimization) [agent-default — operator review required]

Query-surface results return entry metadata (IDs, titles, state, rank) — NOT full entry bodies (spec CON-2). Dispatches fetch bodies separately if needed. This preserves dispatch context budget. Source: spec 025 CON-2 + Principle I.

### DC-2 — Principle VI (State On Disk Is Truth) [agent-default — operator review required]

All state M020 produces lands on disk before each command exits: review-state flips, decision_history entries, graduate/archive back-references, preferences-resolution diagnostics. No in-memory caches that survive across command invocations. Source: spec 025 FR-8 + Principle VI.

### DC-3 — Principle XIV (No Speculative Complexity) [agent-default — operator review required]

CON-3 bounds query surface to exact-match + topic-keyword-index unless dogfood evidence demands escalation. CON-5 caps Jaccard feature vector at frontmatter `title`+`topic`+`tags[]` + first-paragraph 50-token window. NG-5 bounds review UI to text. NG-6 defers decision-history compaction. Source: spec 025 CON-3 + CON-5 + NG-5 + NG-6 + Principle XIV.

### DC-4 — Principle XV (Surgical Precision) [agent-default — operator review required]

CON-4 requires byte-equivalence for frontmatter fields not explicitly listed in the schema-evolution note. No drive-by adjacent edits. Source: spec 025 CON-4 + Principle XV.

### DC-5 — Jaccard threshold default [agent-default — operator review required]

Default threshold is 0.7 (spec A-5 post-weave). Validated against live `knowledge/**/MEM*.md` at M020/P01 kickoff; operator-tunable via FR-6 preferences. Source: spec 025 A-5, clarify answer Q-2.

### DC-6 — Jaccard feature vector shape [agent-default — operator review required]

Feature vector IS: frontmatter `title` + `topic` + `tags[]` keys + first-paragraph content-words capped at 50 tokens (spec CON-5 post-weave). Full-body tokenization deferred to M018 (context-compression). Source: spec 025 CON-5, clarify answer Q-3.
