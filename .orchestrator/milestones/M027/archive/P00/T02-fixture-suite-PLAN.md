## Prerequisites

- T01 has shipped `scripts/diagnostics/metrics-rollup.sh` with the CLI flag surface documented in T01's plan: `--granularity`, `--milestone`, `--phase`, `--task`, `--source`, `--log <path>`.
- The M019 Tier 1 record schema is documented in `scripts/verify/m019-schema.sh`. Required fields per `record_type`:
  - `payload_breakdown`: `{record_type, ts, milestone, phase, task, payload_tokens_estimate, ...}`
  - `dispatch_usage`: `{record_type, ts, milestone, phase, task, source, estimated_cost_usd, pricing_version, ...}`
  - `unit_close`: `{record_type, ts, milestone, phase, task, granularity, source, estimated_cost_usd, pricing_version, verification_pass_rate, deviation_count, retry_count, ...}`
  - Optional: `pricing_warning` (set when `estimated_cost_usd: null`).
- bash 3.2 only on the generator script (CON-7).

## Description

Build a deterministic fixture suite under `tests/fixtures/m027-p00/` that the per-contract verifiers in T03 will run the rollup engine against. Each fixture is a small JSONL file (or a generator script for the perf fixture) crafted to exercise one specific contract. Fixtures are checked into git (except `perf-10mb.jsonl` itself, which is regenerated by `perf-10mb.jsonl.gen.sh` at verifier-run time to keep the repo small).

## Steps

1. **Create the fixture directory** `tests/fixtures/m027-p00/` and a `README.md` documenting each fixture's contract (one paragraph per fixture).

2. **`estimate-only.jsonl`** (FR-3 source-filter): 5 `unit_close` records, all with `source: "estimate"`, mixed across two tasks under one phase under M999. Records carry valid cost+quality blocks. Verifier T03 runs `--source runtime` against this fixture and asserts an empty rollup with "no records match filter"; runs `--source estimate` and asserts a non-empty rollup; runs `--source all` and gets the same as `--source estimate` (since there are no aggregate or runtime records).

3. **`mixed-source-aggregate.jsonl`** (FR-18 / AD-1 aggregation precedence): At granularity `phase` for M999/P00, include:
   - 3 `unit_close` records with `granularity: task`, `source: estimate`, each `estimated_cost_usd: 0.10` (total = 0.30 if naively summed).
   - 1 `unit_close` record with `granularity: phase`, `source: aggregate`, `estimated_cost_usd: 0.50` covering the same M999/P00 scope.
   Verifier T03 asserts: `--granularity phase --milestone M999` yields total cost 0.50 (the aggregate row), NOT 0.80 (aggregate + children). Verifier also asserts the `--granularity task` invocation yields the three task-level rows summed at 0.30 (children visible at their own granularity, not double-counted at the coarser one).

4. **`corrupt-line.jsonl`** (FR-14 corrupt-line tolerance): 10 lines total — 9 valid `unit_close` records + 1 corrupt line in position 4 containing the literal text `{"record_type": "unit_close", BROKEN JSON HERE`. Verifier T03 asserts: rollup exits 0, prints exactly one stderr WARN line containing the line number `4`, and aggregates the 9 valid records.

5. **`missing-fields.jsonl`** (FR-17 input schema validation): 8 lines — 6 valid `unit_close` records plus 2 lines that parse as JSON but lack required fields:
   - One record missing `estimated_cost_usd`.
   - One record missing `granularity`.
   Verifier T03 asserts: the 2 invalid records emit stderr `WARN: input-schema line <N>` diagnostics; only the 6 valid records contribute to totals; exit 0.

6. **`pricing-warning.jsonl`** (FR-11 pricing-warning surface): 5 `unit_close` records — 3 with valid `estimated_cost_usd`, 2 with `estimated_cost_usd: null` and `pricing_warning: "missing"`. Verifier T03 asserts: rollup output for the relevant scope contains a `(2 missing)` suffix on the cost cell.

7. **`pre-m019-mixed.jsonl`** (SC-10 pre-M019 carry-forward): 6 lines — 3 lines that lack `record_type` entirely (legacy pre-M019 log lines, e.g., `{"event": "lock_acquired", "ts": "..."}`) + 3 valid M019 `unit_close` records. Verifier T03 asserts: rollup ignores the 3 pre-M019 lines silently (no stderr WARN) and aggregates only the 3 M019 records; exit 0.

8. **`perf-10mb.jsonl.gen.sh`** (CON-12 / SC-13 perf bound): a small bash script that synthesizes a ~10 MB JSONL file by repeating a template `unit_close` record with varying `task`, `phase`, `ts` fields until the file size crosses 10 MB, then truncates exactly at 10 MB on a record boundary. Generator output path is the script's first argument (default: `tests/fixtures/m027-p00/perf-10mb.jsonl`). Generator script is bash 3.2 compatible. Generator emits exactly one stdout line: the resolved output path. Generator is fast (< 1 s); the verifier T03 invokes it before each perf assertion.

9. **`README.md`** under the fixture dir: one paragraph per fixture explaining the contract it exercises and which FR / SC it maps to. Also documents the fixture-record schema invariants (every `unit_close` carries cost+quality blocks unless explicitly testing a degraded case).

10. **`.gitignore` entry** (in `tests/fixtures/m027-p00/.gitignore` if local, or appended to the project `.gitignore` if that's the convention) for `perf-10mb.jsonl` — the generated 10 MB file is not committed, only the generator script is.

## Constraints

- **CON-7 (bash 3.2)** on `perf-10mb.jsonl.gen.sh`: no `declare -A`, no `<<<`, no `mapfile`, no process substitution. The generator uses a `while [ "$bytes" -lt "$target" ]` loop with `printf` to a file descriptor; size is sampled with `wc -c` (single-script-file shape is not required here — this is emitter-internal code, MEM004 carve-out applies).
- **No real production data**: All milestone IDs in fixtures are `M999` (or `M998`, `M997` for variants) so they cannot collide with real `.orchestrator/milestones/Mxxx/` directories. T03's read-only verifier asserts `git diff --quiet` against the project tree, including the real milestones — fixtures pointing at `M999` make this trivially true.
- **Determinism**: The generator script must produce a byte-identical JSONL when invoked twice with the same arguments (use a fixed seed for any varying field; e.g., `task` = `T$(printf '%02d' $((i % 100)))`, `ts` = a fixed-template incrementing counter).
- **No checked-in 10 MB file**: `perf-10mb.jsonl` itself is gitignored. Only the generator script is committed.
