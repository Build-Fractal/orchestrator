T04 ships the `--repair` flag closing the recovery half of M028 Finding F. Repair walks `~/.claude/settings.json`, removes hook entries whose `(event, matcher, command)` tuple matches a known M025 orphan fingerprint and which lack the `_orchestrator_managed:true` flag, and preserves every other entry verbatim. Strict-tuple match with extra-key guard: a user-authored entry that happens to share a tuple but carries any extra field (description, env, run_in_background, timeout, etc.) is preserved as user-authored. Both pre-T02 wrapper-level flagging and post-T02 leaf-level flagging shapes are honored.

## What Happened

**Installer (`packaging/install/install-claude-code.sh`).** Added `--repair` flag (initial `REPAIR=0`, while-case parser entry mirroring `--uninstall`). Inserted a new `--repair` mode block immediately after the `--uninstall` block and before the adapter-existence sanity check. The block guards on the target file presence (skip-and-exit-0 when absent), invokes `bash $MERGE_HELPER repair --target $hook_target [--dry-run]` with the `$DRY_RUN` composition, propagates the helper's exit code, and short-circuits the rest of the installer flow with `exit 0`. No probe, no payload staging, no runtime staging — repair is a one-shot cleanup, not a re-install.

**Settings merge (`scripts/util/settings-merge.sh`).** Added a `repair` subcommand parallel to the existing `merge` and `uninstall` arms. The python3 heredoc reads target JSON (exit 4 on parse failure, matching merge/uninstall semantics), walks `target.hooks` event-by-event, and applies the wrapper-OR-leaf managed-detection rule: a wrapper carrying `_orchestrator_managed:true` at wrapper-level OR any-leaf-level is KEPT verbatim. Unmanaged wrappers undergo per-leaf strict-tuple match against the hard-coded `ORPHAN_TUPLES` set (`{(Stop, "", orchestrator-post-verify), (PreToolUse, Bash, orchestrator-before-commit)}`) with the `ALLOWED_LEAF_KEYS={type, command}` guard — leaves with extra fields are preserved as user-authored. Cascade cleanup matches the existing uninstall path: empty wrapper drops; empty event array drops the event key; empty hooks object drops the hooks key. Write mode emits `repaired=N preserved=M`; `--dry-run` emits per-line `would_remove=event:matcher:command` and `would_preserve=event:matcher:command` lines plus a `would_repair=N would_preserve=M dry_run=1` summary.

**Canonical fixture (`tests/fixtures/m028-post-repair-canonical.json`).** Generated from the P01/T02 pre-repair fixture by applying the repair algorithm and serializing via `json.dumps(..., indent=2, sort_keys=True)` — the exact serializer used by settings-merge.sh, ensuring SHA-256 byte-equality at gate time. The post-repair shape: 12 unflagged orphans removed (5 Stop + 7 PreToolUse Bash); 4 entries preserved (1 PostToolUse user-authored + 1 SessionStart user-authored + 1 PreToolUse Bash flagged + 1 Stop flagged). All non-hooks top-level keys (model, statusLine, theme, effortLevel, enabledPlugins, extraKnownMarketplaces, feedbackSurveyState, $schema) survive structurally.

**Verifier (`scripts/verify/m028/p02-repair-fixture.sh`).** AD-19 single-script-file flat shape, bash 3.2 + POSIX-sh-safe, no jq. Stages the pre-repair fixture into an isolated HOME (`${TMPDIR:-/tmp}/p02-repair-$$/.claude/settings.json`), runs `HOME=$tmp_home bash $INSTALLER --repair`, computes SHA-256 of the result via `shasum -a 256 <file> > tmp.sha; awk '{print $1}' tmp.sha` (avoids `$(... | ...)` compound and `$(cmd <file)` nested redirect, both AP-006 forbidden inside AD-19-conformant scripts), asserts byte-equality with the canonical fixture's SHA-256, then re-runs `--repair` to lock idempotency-by-construction. Cleans up the tmp dir on PASS only — leaves it on FAIL for inspection.

## Deviations

**Wrapper-OR-leaf managed-detection vs spec algorithm step 3 leaf-only language.** The task plan's algorithm at step 3 said "If leaf has `_orchestrator_managed: true`, KEEP". The P01/T02 canonical pre-repair fixture, however, deliberately carries the `_orchestrator_managed:true` flag at the wrapper level (lines 80 and 142 of `m028-pre-repair-snapshot.json`), modeling the pre-T02 transitional shape as P01/T02's summary documents ("5 unflagged + 1 flagged Stop entries; 7 unflagged + 1 flagged PreToolUse Bash entries"). Strict leaf-only interpretation would have dropped the inner leaf via the orphan-tuple match, then cascade-dropped the now-empty wrapper — eliminating the 4 preserved entries the spec Truth wording requires ("preserves user-authored entries verbatim"). Wrapper-OR-leaf interpretation honors both shapes (post-T02 leaf-level emission from T02's adapter AND pre-T02 wrapper-level residue from real downstream user systems) and is the load-bearing mapping from the spec's high-level guarantee to the algorithm. Captured as a key decision rather than a DEVIATION because the spec Truth and the canonical fixture together unambiguously imply this read; the leaf-only language in the algorithm prose is a sub-statement that the wrapper-level case extends.

## Dogfood Findings

1. **Repair-side pre-T02 wrapper-flagged shape is a real concern, not just a fixture artifact.** The P01/T02 canonical pre-repair fixture carries `_orchestrator_managed:true` at the wrapper level (not the leaf level). The post-T02 adapter (`scripts/dispatch/adapters/runtime/claude-code.sh`) emits the flag at the leaf level. Real downstream user systems that installed pre-T02 will have wrapper-flagged residue alongside any post-T02 reinstall's leaf-flagged entries. Repair's wrapper-OR-leaf detection rule absorbs both shapes. Worth capturing because future settings-merge.sh changes (e.g., a hypothetical normalize-managed-flag pass) need to preserve this tolerance — collapsing the two shapes into one position would erode the flexibility T04 builds in.

2. **Existing `uninstall` arm uses leaf-only managed detection.** `scripts/util/settings-merge.sh` lines 313-317 (`uninstall` python body) check `any_managed` at the leaf level only, ignoring wrapper-level flags. A pre-T02-installed user running `--uninstall` today on a wrapper-flagged settings.json will leave the wrapper-flagged entries behind (uninstall-incomplete). T04's repair fixes this for the repair path; uninstall does not. **Suggested CLAUDE.md hotfix-list entry**: extend `uninstall` to use the same wrapper-OR-leaf detection T04's `repair` introduces — symmetric guarantee, ~10-line patch. Bundle into the next M025-touching paper-cut sweep.

3. **Plan algorithm prose vs canonical fixture shape drift.** The task plan's step 3 algorithm description used leaf-only language; resolving the apparent gap required reading both the P01/T02 fixture shape and the spec Truth's preservation wording. **Suggested fix**: `commands/plan-phase.md` could specify that algorithm prose interacting with a fixture explicitly references the fixture shape it must satisfy ("applied to the canonical fixture, the algorithm produces N entries removed and M preserved"). Cheap insurance against algorithm-prose / fixture-shape drift at planning time.
