T04 authored three per-finding end-to-end verifiers under scripts/verify/m028/, each a flat AD-19 single-script-file (bash 3.2 + POSIX-sh-safe, no jq) that exercises its target wrapper end-to-end and asserts both happy-path and boundary contracts.

finding-D-verifier.sh stages an isolated tmp tree mirroring .orchestrator/milestones/<MID>/phases/<PID>/tasks/*.txt with 4 stale .txt files spread across two phases, copies cleanup-stale-results.sh into the tmp scripts/util/ so its self-relative REPO_ROOT resolves to the tmp tree, and asserts: case 1 exit 0 + REMOVED=4 + RESIDUAL=0 + OK terminator (multi-phase happy path); case 2 path-escape ID '../escape' -> exit 2 (boundary refusal); case 2b absolute path '/etc' -> exit 2 (boundary refusal); case 3 valid M998 ID with no tree -> exit 1. The boundary-refusal pair is the load-bearing Finding D contract — without it the wrapper would reproduce the unbounded /bin/rm -f Screenshot 2 hazard.

finding-E-verifier.sh exercises grep-files.sh and node-eval.sh end-to-end against staged tmp inputs. grep-files.sh: stage two .sh files containing 'classify_command' invocations, run wrapper, assert exit 0 + 2 '--- ' separators (one per file) + at least 2 matches. node-eval.sh: stage probe.js that prints 'FINDING_E_NODE_OK', invoke wrapper, assert rc=0 and stdout matches. Node block guarded by 'command -v node' and emits SKIP: if node is not on PATH (verifier still passes). Per the plan, the verifier asserts operational reachability of the wrappers, NOT how an agent picks them — discoverability is documentation's job (T03).

finding-G-wrapper-verifier.sh is the wrapper-side complement of finding-G-classifier-verifier.sh (P03). Stages a tree with 4 T*-SUMMARY.md files across M001/M002/M066, cd's into the tmp dir, and asserts: case 1 peek-files.sh 'T*-SUMMARY.md' --max 3 --lines 20 -> exit 0 + exactly 3 '--- ' separators (--max enforced); case 2 --exclude M066 -> 'EXCLUDED' substring absent from output; case 3 wrapper-source self-conformance — peek-files.sh code (with comment lines stripped) contains no 'sh -c '' literal. Together with the P03 classifier verifier, the loop closes: classifier rejects bad shape, wrapper produces good output without rebuilding the shape internally.

Plan deviation on case 3: the plan specified a raw 'grep -q "sh -c "' source check, which produced a false-positive FAIL because peek-files.sh's docstring legitimately references the AP-014 shape it replaces. Adjusted the case-3 check to grep non-comment lines only via 'grep -v ^[[:space:]]*#' into a tmp file before the literal scan. The contract intent (wrapper does not invoke sh -c internally) is preserved; the documentation-comment false positive is closed. Documented inline in the verifier.
