T02 ships the autonomous-loop replay harness `tests/run-downstream-fixture.sh` (~190 lines, AD-19 single-script-file flat shape, bash 3.2 + POSIX-sh-safe, no jq) plus the cross-cutting Truth-Check verifier `scripts/verify/m028/p05-downstream-fixture-clean.sh` (~62 lines, same shape constraints). Both files are co-authored by this task per the CLAUDE.md plan-time verifier-availability discipline -- no cross-task verifier dependency.

The harness stages the M028 hooks payload into an isolated `HOME` (`${TMPDIR:-/tmp}/m028-p05-replay-$$`) by invoking `packaging/install/install-claude-code.sh --project-dir <tmp>` with `HOME=<tmp> CLAUDECODE=1`, then routes nine synthetic Bash hook events through the staged `pre-bash-shape-guard.sh` and one Stop event through the staged `after-verify-sync.sh`. `CLAUDE_PROJECT_DIR` is set to a non-orchestrator-repo path (`<tmp>/fake-project`) to mirror Finding A's wild context (the hook self-locates the classifier via `BASH_SOURCE[0]` per P02/T01's resolution fix).

Hook event coverage:
- 1x Finding A 4-connector compound chain (`echo a && echo b && echo c && echo d`) -- guaranteed AP-009 / compound-chain-gt2 reject under both M021 and M028 classifiers; matches `finding-A-verifier.sh` canonical assertion.
- 6x M028 corpus IDs 21..25 + 27 verbatim INPUT bytes (AP-010 cmd-sub-in-pattern; AP-011 quoted-arg-newline-hash; AP-012 multiline-quoted-script; AP-013 unquoted-brace-glob; AP-014 xargs-sh-c-compound-body; AP-014 boundary case via outer body with nested sh -c whose body is opaque-treated per CON-5 one-level-deep recursion bound). Extracted at runtime via the `extract_corpus_input` helper that mirrors the awk grammar in `tests/run-prompt-corpus-replay.sh:58-71` (`^ID: ` + `^INPUT: ` substr extraction) and decoded via `printf %b` for the literal-backslash-n escape sequences (ID 22 carries a real LF; ID 25 carries UTF-8 box-drawing bytes).
- 1x negative-control allow-form command (`echo hello`) -- M021 regression catch-all per CON-7 strict-superset.
- 1x Stop event invocation of `after-verify-sync.sh` -- asserts exit 0 + no `command not found` substring on stderr (the Finding F regression failure mode).

Final harness output: `WOULD_PROMPT=0/9` summary line + `PASS: tests/run-downstream-fixture.sh` verdict line + exit 0. The 9 in the denominator counts the 1 Finding A + 6 corpus + 1 negative-control + 1 Stop event assertions.

Helper-function carve-out applied: `pass`, `fail`, `invoke_hook`, `extract_corpus_input` live as bash function bodies whose contents are NOT scanned by the AP-009 inline-shape classifier per the M028/P02/T05 codification. The harness's JSON event payload is authored via `printf '{"tool_name":"Bash","tool_input":{"command":"%s"}}\n' "$safe"` rather than a heredoc to avoid the AP-008 heredoc-with-expansion shape; `safe` is escape-encoded (`\` -> `\\`, `"` -> `\"`, real LFs -> JSON `\n`) before injection -- mirrors the canonical pattern in `tests/run-prompt-corpus-replay.sh:101-107`.

Plan-departure recorded: the task plan's `extract_corpus_input` example used the awk pattern `^# ID:` (a stale grammar from a draft that prefixed corpus IDs with `# `). The actual corpus uses the unprefixed `ID: ` grammar and the canonical `tests/run-prompt-corpus-replay.sh:68` parser uses `^ID: ` -- the harness as shipped uses the canonical form so the corpus extraction round-trips. The plan's `decoded` injection into JSON was also missing the real-LF -> JSON `\n` re-encoding that the canonical harness performs at line 105; the harness as shipped includes the re-encoding so ID 22 (literal-LF AP-011 evidence) round-trips through the JSON event payload without breaking the parser on the hook side.

Plan-departure recorded: the task plan's Stop event PASS message was `Stop event after-verify-sync.sh -> exit 0 (no 'command not found')`. The literal substring `'command not found'` inside the PASS message caused the Truth-Check verifier's `grep -q 'command not found'` clean-output assertion to false-fail. Replaced with `Stop event after-verify-sync.sh -> exit 0 (clean stderr)` so the PASS message no longer carries the substring the clean verifier is grepping against. Worth threading into the next M028 paper-cut sweep as a CLAUDE.md hotfix entry: when a verifier asserts the absence of a literal substring in subprocess output, the subprocess MUST NOT emit that substring as part of its own success messages.

`scripts/verify/m028/p05-downstream-fixture-clean.sh` invokes the harness with `bash $HARNESS > $tmp_out 2>&1`, then asserts (a) harness exit 0; (b) `^WOULD_PROMPT=0/[0-9]+$` line present (grep -E since bash 3.2 has no anchored digit-class regex); (c) no `command not found` substring; (d) at least one `^PASS:` line. 4 PASS rows + final `PASS: p05-downstream-fixture-clean.sh` verdict line + exit 0.
