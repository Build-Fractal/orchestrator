T05 closes M035 P02 by shipping the bundle-hygiene pre-publish filter (#Q-9 absorption) and the phase-suite aggregator. Two filter rules land per the bundle-hygiene proposal: **rule 1** pattern exclusion (basename `m[0-9]*-p[0-9]*-*` under `scripts/verify/`, `tools/verify/`, `templates/conversus-presets/`) which kills the bulk milestone-internal verifier corpus in one rule; **rule 2** magic-comment opt-out (header line within first 10 lines matching `bundle: dogfood-only`) which is self-documenting for future authors. Both rules are mirrored in two surfaces: build-time (`packaging/bundle/build-bundle.sh apply_bundle_hygiene_filter` post-copy pass invoked from `cmd_build`) and publish-time (`.npmignore` family enforcing rule 1 against the npm tarball).

**Key learning during execution: per-subdir `.npmignore` is the actually-load-bearing layer.** Initial implementation followed the payload literally — a root `.npmignore` with patterns like `scripts/verify/m[0-9]*-p[0-9]*-*`. Re-running the npm-pack-contents verifier showed `FAIL: tarball scripts/verify/ contains 796 dogfood verifiers`. Investigation revealed npm's documented behavior: when `package.json` `files:` whitelist is present, root `.npmignore` is largely subordinate for top-level entries, but per-subdirectory `.npmignore` files INSIDE whitelisted subtrees DO apply. Adding `scripts/verify/.npmignore` (with patterns `m[0-9]*-p[0-9]*-*` + `m[0-9][0-9][0-9]/` + `m[0-9][0-9][0-9]-*/` to also catch `m028/`-style directory shapes) dropped the count to zero. Root `.npmignore` retained as defense-in-depth and as a discoverable maintainer pointer; `templates/conversus-presets/.npmignore` added in parallel for the third pattern-exclusion subtree (no current dogfood content in that dir but the contract surface is what matters).

The `should_exclude_from_bundle()` function (~40 lines) and `apply_bundle_hygiene_filter()` post-copy filter (~25 lines) land at the top of `packaging/bundle/build-bundle.sh` (after `EXPECTED_HOOK_EVENTS` declaration, before `resolve_version()`). Integration is a single line at the end of `cmd_build`: `apply_bundle_hygiene_filter "$BUNDLE_DIR"`. The post-copy approach was preferred over converting the existing per-skill `cp` loop into a `find`-pipe because the existing M032 `--check` contract iterates by name and the conversion would have rippled. Current `BUNDLE_DIR` has no `scripts/verify/` subtree, so the build-time filter is a no-op today; the contract+verifier surface is what T05 is measured by, and the build-time filter is load-bearing for any future channel that does stage milestone-internal content.

The bundle-hygiene-filter verifier `tools/verify/m035-p02-bundle-hygiene-filter.sh` ships 10 grep-contract surfaces (file existence × 2 + 6 source-shape assertions on `build-bundle.sh` + 2 source-shape assertions on `manifest.yml`) and emits `BATTERY: pass=10 fail=0`. The verifier asserts the filter logic CARRIES in source code rather than running build-bundle and counting excluded files — works regardless of bundle dir state.

The npm-pack-contents verifier `tools/verify/m035-p02-npm-pack-contents.sh` runs actual `npm pack` against the repo, extracts the resulting tarball into a temp dir, and asserts 19 surfaces: 8 required-present (`package.json`, `bin/orchestrator`, `packaging/install/install-claude-code.sh`, `packaging/npm/postinstall.sh`, `commands`, `scripts`, `templates`, `references`); 10 required-absent (`.orchestrator`, `specs`, `tests`, `tools`, `docs`, `wiki`, `.git`, `.github`, `.planning`, `node_modules`); 1 dogfood-exclusion check (zero `m[0-9]*-p[0-9]*-*` files under tarball `scripts/verify/`). All 19 PASS. The verifier carries a SKIP path when `npm` is not on PATH (defers to CI); on this executor `npm 11.6.2` is on PATH so the real-tarball check exercised end-to-end.

The phase-suite aggregator `tools/verify/m035-p02-phase-suite.sh` runs all 8 task-grain verifiers in T01→T05 order (`m035-p02-package-json-shape.sh`, `m035-p02-bin-entry.sh`, `m035-p02-postinstall-shape.sh`, `m035-p02-installation-doc-exclusion-list.sh`, `m035-p02-byte-equivalence-skeleton.sh`, `m035-p02-release-workflow-shape.sh`, `m035-p02-bundle-hygiene-filter.sh`, `m035-p02-npm-pack-contents.sh`), redirects each verifier's stdout to `/dev/null` and stderr to a per-pid scratch file, emits one PASS/FAIL line per verifier, and emits the canonical `BATTERY: pass=N fail=N` line at the bottom. Canonical pattern for pruning dogfood content from inside whitelisted dirs. (2) **contract-via-grep-of-source-not-runtime** for the build-time filter verifier — works regardless of whether the current bundle dir contains dogfood content. (3) **real-tarball-as-real-bundle-smoke** (Plan-Time Discipline Rule 5 analog) — npm-pack-contents runs actual `npm pack` and inspects staged tarball, no mock equivalent. (5) **single-script-find-with-exec-rm-form** satisfies AP-009 single-script-shape without needing `run-probe.sh` wrapper.
