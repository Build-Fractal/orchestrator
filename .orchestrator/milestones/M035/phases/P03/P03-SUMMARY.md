## What was built

P03 establishes the Homebrew tap publishing channel for `orchestrator` end-to-end and lights up the load-bearing CON-5 / Constitution Principle XVI cross-channel byte-equivalence assertion:

- **T01 — Formula template + render script**: `packaging/homebrew/orchestrator.rb.tmpl` is a minimal Ruby DSL formula carrying three substitution tokens (`__VERSION__` / `__URL__` / `__SHA256__`). `render-formula.sh` is a bash 3.2 token-substitution helper that validates `--sha256` shape (64 lowercase hex) and writes the rendered formula to stdout. FR-9 honored: `def install` does filesystem staging only — `prefix.install Dir["package/*"]` flattens the npm tarball's `package/` wrapper, `bin.install_symlink prefix/"bin/orchestrator"` wires the binary onto PATH. No `depends_on`, no `on_macos`/`on_linux`, no formula-specific install logic. D007 records the architectural decision: re-use the P05-signed `npm pack` tarball as the homebrew url source.
- **T02 — `release.yml` `homebrew-publish` job + CON-6 negative-assertion**: third sibling job, `needs: npm-publish` (so the tarball is on the GitHub release before the formula references it), gates on the same tag-push-only condition as npm-publish for CON-6 symmetry. Six-step chain: checkout / resolve version+URL / download SHA256SUMS via `gh release download` / extract digest via awk / render formula / clone tap with `HOMEBREW_TAP_TOKEN` PAT (https x-access-token form) / write `Formula/orchestrator.rb` + push to tap's `main` with `formula: bump to v<X.Y.Z>`. `pr-validate` extended with the symmetric `CON-6 — assert no HOMEBREW_TAP_TOKEN access` runtime check (em-dash U+2014 preserved). D008 records the PAT scoping decision: fine-grained, `Build-Fractal/homebrew-orchestrator:contents:write` only.
- **T03 — Cross-channel byte-equivalence assertion**: replaces the P02-era `SKIP: pending P03` stub in `tests/m035-acceptance/cross-channel-byte-equivalence.sh` with a real arm that re-uses the `npm pack` tarball (D007) and stages it into a fixture Cellar layout matching the formula's `def install`. The cross-channel equality assertion `[ "$NPM_HASH" = "$HOMEBREW_HASH" ]` is now the load-bearing CON-5 test. End-to-end verified: `NPM_HASH = HOMEBREW_HASH = c222132ce45a03f433917aeb65f2b9cd5f2c0e97a684098bd1de1f5e1945b46b`. New `_exclusion-list-by-channel.sh` helper extracts per-channel paths from `references/installation.md` at runtime; the per-channel exclusion union is pre-computed in the caller (decision flagged in plan-phase) so the existing `_byte-equivalence-hash.sh` contract stays unchanged. Post-dispatch BSD-sed portability fix replaced `\s` with POSIX `[[:space:]]` in PKG_VERSION extraction — without it, macOS sed silently no-ops the substitution and leaks the matched line into the staged Cellar path.
- **T04 — Operator docs + phase-suite aggregator**: `references/installation.md` extended with `## Installing via Homebrew` (consumer-facing) and `## Releasing via Homebrew` (operator-facing — MOS-1 tap creation, MOS-2 PAT generation with the exact fine-grained scope-narrowing recipe, D008 rotation cadence). `commands/update.md` extended with a `## Update sources` H2 listing all three dispatches (git/npm/homebrew). `tools/verify/m035-p03-phase-suite.sh` chains all seven per-truth verifiers and emits `BATTERY: pass=7 fail=0 skip=0`.

## Plan-phase Open Questions resolved

- **#Q-P03-1** (homebrew tarball source) → re-use P05-signed `npm pack` tarball (D007). Rationale: CON-5 byte-equivalence is structural, not channel-specific; a separate brew-tarball would mask divergence rather than expose it.
- **#Q-P03-2** (tap-push mechanism: PAT vs GitHub App) → `secrets.HOMEBREW_TAP_TOKEN` fine-grained PAT, scoped to one repo + `Contents:write` only (D008). Rationale: symmetry with NPM_TOKEN precedent + lower friction than GitHub App ownership semantics + clean fast-follow if rotation friction surfaces.
- **#Q-T03-exclusion-filter** (per-channel exclusion-list handling: extend `_byte-equivalence-hash.sh` with a `CHANNEL=` env var vs pre-compute exclusion union in caller) → pre-compute in caller. Rationale: leaves the helper's contract unchanged for existing P02 consumers; the caller already has the channel context.

## Patterns established

- Homebrew formula template with bash render script (token substitution, no in-place writes, sed `|` delimiter for URL slashes).
- Cross-channel tarball reuse (D007) as the single source-of-truth for byte-equivalence — independent build paths would mask CON-5 divergences.
- Fine-grained PAT scoped to one repo + Contents:write only (D008) as the canonical cross-repo-write pattern; GitHub App migration is a clean fast-follow.
- Per-channel exclusion union pre-computed in the caller — keeps the byte-equivalence helper's contract stable across channel additions.
- BSD-sed portability via POSIX character classes (`[[:space:]]` over `\s`).
