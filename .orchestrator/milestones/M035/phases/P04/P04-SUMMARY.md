## What was built

P04 establishes the curl-pipe-bash publishing channel for `orchestrator` end-to-end and lifts the load-bearing CON-5 / Constitution Principle XVI cross-channel byte-equivalence assertion from a 2-way to a 3-way equality:

- **T01 — `packaging/install/install.sh` + D009**: bash 3.2 / POSIX-sh-safe runtime-detect + tarball-fetch + dispatch wrapper that lands on the GitHub release as a signed asset and is the target of `curl -sSL <url> | bash`. Production path resolves `VERSION=latest` via a jq-free `grep+sed` parse of `api.github.com/.../releases/latest`, downloads the tarball + `SHA256SUMS`, runs `shasum -a 256 -c SHA256SUMS --ignore-missing`, extracts via `tar -xzf` into a `mktemp -d` staged dir, flattens the npm `package/*` convention, gates on `~/.claude` for CC-only v1 runtime detection (Codex CLI / Cursor advisory + exit 2 per M009 fast-follow positioning), and dispatches `bash <STAGED>/packaging/install/install-claude-code.sh --project-dir <ORIG_PWD>`. Test-mode hooks `M035_P04_LOCAL_TARBALL` + `M035_P04_STAGE_ONLY` + `M035_P04_STAGE_DIR` are default-OFF and short-circuit download/SHA-verify/dispatch for T03 byte-equivalence. D009 records the URL-host decision: GitHub release asset URL — `latest/download` for unpinned + `download/v<X.Y.Z>/` for pinned; symmetric with D007 npm+homebrew release-asset distribution; reversible to a polished short URL post-launch via one-line DNS change.

## Patterns established

- Curl-pipe-bash installer shape (jq-free grep+sed JSON parse, mktemp staging, npm `package/*` flatten via `cp -R + rm`, single-runtime detection for CC-only v1).
- Load-bearing default-off test-mode env vars (`M035_P04_LOCAL_TARBALL` / `M035_P04_STAGE_ONLY` / `M035_P04_STAGE_DIR`) — production path byte-identical when unset; T03 is the consumer that proves they pull their weight.
- Additive glob-driven release-artifact extension — new artifacts land in `release-artifacts/` via `cp`/`mv`; downstream cosign-loop + SHA256SUMS + `gh release create release-artifacts/*` pick up new files automatically without per-channel logic.
- Job-level `timeout-minutes` with CON-comment cross-reference — per-job timeout is GitHub-Actions native (workflow-level doesn't exist); inline CON-8 annotation surfaces rationale to future plan-phase authors.
- Regression-guard via negative-grep (`secrets\.(CURL|INSTALL_SH|PIPE_BASH)` failing-if-matched) catches future plan-phase authors accidentally introducing a curl-channel secret.
- Test-IS-the-smoke functional verifier — run the test end-to-end with stdout captured to a tempfile, grep the captured log for the canonical PASS message; distinguishes 3-way-PASS from 2-way-fallback-PASS from genuine FAIL while staying AP-009-safe.
- 3-way supersedes 2-way with fallback preservation — assertion ladders gracefully when arms are unavailable.
- Two-H2-section-append-at-EOF (consumer-facing `## Installing via X` + operator-facing `## Releasing via X`) — symmetric with P03 T04's homebrew pair.
- Inline D-number rationale blocks in operator prose — operators reading installation.md don't need to context-switch to DECISIONS.md; structurally enforced by verifier grepping for literal D-numbers.
- BSD-grep-safe flag pattern — `grep -qF -- '--uninstall'` is the portable shape when the pattern starts with `--`.
