## What was built

P06 closes M035 by shipping multi-source dispatch for `orchestrator:update`, the JSONL emission contract that observes each dispatched channel, and the milestone-grain acceptance battery that gates `validate-milestone.sh M035` and the milestone-close artifacts.

- **T01 — `update_source` config schema (D012)**: appended `update_source` to `scripts/state/read-config.sh` `VALID_KEYS`; recorded **D012** in `.orchestrator/DECISIONS.md` with the canonical `### D### — title` heading shape continuing D007–D011. The schema enumerates `git|npm|homebrew|none`; curl-pipe-bash users collapse to `npm` because curl-pipe-bash extracts the npm tarball (D007/D009 single-source-of-truth). Literal `none` is the operator opt-out: short-circuits both dispatch and drift-render with no warning. Verifier `m035-p06-config-schema-shape.sh` BATTERY pass=7.

- **T02 — Multi-source dispatch + AD-5 detection (D014)**: added `resolve_update_source` + `persist_update_source` helpers and a four-arm `case "$update_source"` block to `scripts/lifecycle/run-update.sh`. Detection order per **D014**: (1) `install-meta runtime=` field discriminator, (2) `npm root -g` symlink presence, (3) `brew --prefix` Cellar receipt, (4) `git` fallback. First-match wins; detected non-`git` sources are persisted back to `.orchestrator/config.yml` so subsequent runs short-circuit to read-from-config. Verifier `m035-p06-multi-source-dispatch-shape.sh` BATTERY pass=13.

Known paper-cut surfaced at P02 close, unblocking but unresolved; future decisions either pick a single shape or extend the rebuild-index reader to handle both.

Removed inline as part of milestone-close ordering rather than deferring to a follow-up paper-cut. Same shape as the T05.5 reconciliation pattern.
- **BSD-sed bracket-class papercut from P03/P05** (post-launch follow-up): `tests/m035-acceptance/_byte-equivalence-hash.sh` `EXCLUSION_LIST` mechanism is a no-op locally on macOS BSD sed. Tests pass today because the channel arms hash flat tarball-extracts identically; cross-channel hardening is post-launch scope.
- **Live-channel evidence (MOS-3/MOS-4/MOS-5)**: deferred to first-release time per spec — exercised on the first published `v*` tag through `.github/workflows/release.yml`. Until then the channels are statically verified (template/script/workflow shape + byte-equivalence simulation) but the live `brew install` / `curl … | bash` / synthetic-tag-push paths are unproven on a live registry/release.
- **Rollback-byte-equivalence test detaches host-repo HEAD** (post-launch paper-cut): `tests/m035-acceptance/m035-p05-rollback-byte-equivalence.sh` invokes the rollback driver against the host repo as the source-repo; the driver's `git checkout <prior-sha>` leaves HEAD detached even when the prior-SHA equals current-HEAD. Operators (and orchestrator-loop dispatchers) must run `git checkout main` after every battery / phase-suite invocation.
- **M032 SC-5 fixture-completeness skip carried through**: `wiki-init.sh --deploy` bundle-staging recommended fix-during-M035 closure but deferred. Operator follow-up: extend `wiki-init.sh --deploy` to bundle-stage `wiki-deploy.sh` from `$REPO_ROOT` if missing in `$PROJECT_DIR`.
