Mid-task correction (validator quote-stripping):

The first run of m036-p04-tier-2-block-not-promoted.sh failed with "stdout missing BLOCKED line" because the driver's classify_reference_file delegate (-> tools/verify/lib/p00-validate-chunk-frontmatter.sh, M036/P00 deliverable) was rejecting all M036/P04 fixtures — the validator stripped leading whitespace and trailing whitespace from the category: line but did NOT strip surrounding double quotes. All M036/P04 fixtures use the quoted form (category: "cms-rule") per the M036 frontmatter contract; the validator was authored expecting the unquoted form (which is what its own internal tests inline-author). The classifier was therefore short-circuiting every chunk to REJECTED before the driver ever reached the tier_2_verdict gate.

This bug is upstream of T03 (P00 deliverable) but was not surfaced earlier because T02's idempotency verifier exercises only the byte-identical-tree contract (which is trivially satisfied when nothing is CREATED) and the other T02 verifiers are token-presence shape checks that don't exercise the end-to-end ingest path. T03 is the first M036/P04 verifier that drives the full ingest path against a real fixture, so it is the first to surface the validator quote-stripping gap.

Fix: extended the sed pipeline in tools/verify/lib/p00-validate-chunk-frontmatter.sh CATEGORY/TIER extractors to additionally strip surrounding single OR double quotes (sed -E 's/^"//; s/"$//; s/^'"'"'//; s/'"'"'$//'). Applied in both the file-arg branch and the stdin branch. Re-ran the existing P00 validator test suite (tools/verify/p00-taxonomy-rejects-unknown.sh) — still PASS (validator behavior on unquoted inputs unchanged). Re-ran the M036/P00 phase suite — pass=8 fail=0 unchanged.
