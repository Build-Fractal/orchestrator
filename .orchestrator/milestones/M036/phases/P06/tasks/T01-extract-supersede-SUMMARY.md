T01 lands the supersede-chain authoring branch on top of the M036/P02 + M036/P04 content-hash idempotency baseline. The extract driver (scripts/knowledge/extract-reference.sh) now distinguishes three paths on the chunk-existence gate: (a) bare-suffix file absent — first-time extraction, byte-equivalent to the P02 fast-path; (b) bare-suffix file present AND chain-tip content_hash matches new source hash — emits SKIPPED reason=unchanged, byte-equivalent to the P02 fast-path on unchanged corpora (load-bearing CON-5 invariant cited in the dispatch's critical instruction); (c) bare-suffix file present AND chain-tip content_hash differs from new source hash — supersede branch fires: walks to the chain tip via supersede_find_chain_tip, computes the next slot via supersede_next_version, retargets chunk_file to REF-<cat>-<id>-v<N+1>.md, writes the new chunk with version: <slot> + supersedes: "<prior-id>" frontmatter, amends the prior tip's frontmatter with superseded_by: "<new-id>" via supersede_amend_prior_chunk (idempotent), and emits SUPERSEDED: <prior-id> -> <new-id> on stdout in addition to the existing EXTRACTED: line for the new successor.

**What was built**:

- **scripts/knowledge/lib/extract-supersede.sh** (~95 lines, pure-lib MEM004; no top-level execution; sourceable from any caller). Three functions:
  - supersede_find_chain_tip(chunk_dir, category, cite_id) — emits the absolute path of the current chain-tip file; bare-suffix counts as version 1; the highest -vN.md present wins; exits 1 if no chunk file exists yet.
  - supersede_next_version(chunk_dir, category, cite_id) — emits the next free integer version slot; returns 1 when no chunk file exists yet (first-time path; caller should not invoke).
  - supersede_amend_prior_chunk(prior_file, new_chunk_id) — mutates prior chunk frontmatter in-place to insert superseded_by: "<new_chunk_id>" after the existing content_hash: line via awk-into-tmpfile-then-mv (BSD-sed/GNU-sed portable; macOS-safe); idempotent — if the exact superseded_by: line is already present, no-op.

- **scripts/knowledge/extract-reference.sh** (modified — sources lib/extract-supersede.sh after the existing helper sources at line 36; expands the chunk-existence gate at lines ~115-137 to add the supersede branch on content-hash mismatch; stamps version: <slot> + supersedes: "<prior-id>" into chunk frontmatter on the supersede path; emits SUPERSEDED: stdout immediately before the existing EXTRACTED: line). The SKIPPED fast path is preserved byte-equivalently for unchanged corpora because supersede_find_chain_tip returns the bare-suffix file when no -vN.md successors exist — gate semantics are identical.

- **tools/verify/m036-p06-extract-supersede-shape.sh** — token-presence verifier on the driver: 10 checks asserting the supersede branch tokens (sourced helper, three function calls, SUPERSEDED: prefix, supersedes: + version: stamping, REF-${category}-${cite_id}-v naming, preserved SKIPPED fast path, M036/P06 attribution comment).

- **tools/verify/m036-p06-extract-supersede-helper-shape.sh** — token-presence verifier on the helper lib: 6 checks (three function definitions, MEM004 attribution, set -eu strict, "Pure-lib MEM004 helper" no-top-level-exec marker).

**Patterns established**:

- **Pure-lib MEM004 carried into the supersede surface** — extract-supersede.sh exposes function definitions only (supersede_find_chain_tip, supersede_next_version, supersede_amend_prior_chunk) with no top-level execution; sourceable from the driver and from any future test harness or downstream task. Same shape as the M036/P02 lib/extract-* helpers and the M036/P04 classify-reference.sh.
- **Bare-suffix-counts-as-v1 chain-walk convention** — the first chunk for a cite_id lives at REF-<cat>-<id>.md without a version suffix; second-and-later live at REF-<cat>-<id>-v2.md, REF-<cat>-<id>-v3.md, etc. Bare-suffix counts as version 1; the next-free-slot helper does NOT double-count it (the for f in ... -v*.md loop only matches explicitly-versioned successors). Documented in the helper header comment and verified by the end-to-end verifier producing -v2 (not -v1) on the first supersede.
- **awk-into-tmpfile-then-mv frontmatter amendment pattern** — supersede_amend_prior_chunk inserts the superseded_by: line after the existing content_hash: line via awk piped to a mktemp tmpfile then mv-rename, sidestepping the BSD-sed-vs-GNU-sed -i syntax disagreement. Reusable for any future M036 frontmatter amendment.
- **Idempotent amend-pass via grep-qF-pre-check** — the helper short-circuits with no-op if grep -qF -e 'superseded_by: "<new-id>"' already matches in the prior file, so re-running the supersede branch on the same mutation pair leaves the prior chunk byte-identical.
- **Chain-tip gate (not bare-suffix gate) for content-hash idempotency** — when a chain exists, the gate must compare against the LATEST version's content_hash, not the bare-suffix file's (which holds an older version's hash post-supersede). For unchanged corpora chain-tip == bare-suffix and behavior is byte-identical to the P02 fast-path; the change is invisible to operators on the unchanged-corpus path. Load-bearing for the third-run-emits-SKIPPED contract that restores idempotency after a supersede has fired.
- **Behavioral verifier under markdown-floor-only host-independence** — m036-p06-supersede-chain-end-to-end.sh stages source.md + manifest.yaml in mktemp -d, drives the driver three times, and asserts both filesystem-state (chunk files present, prior frontmatter amended) and stdout-state (SUPERSEDED: + SKIPPED: lines emitted) without any pdftotext/pandoc dependency. Carried from the M036/P02 idempotency-verifier pattern.
- **M036 verifier conventions inherited intact** — milestone-prefixed slug (m036-p06-*), AD-19 single-script-file shape, set -eu strict, grep -qF -e leading-dash-safe token-loops, ROOT resolution via ${ORCHESTRATOR_ROOT:-$(pwd)}, structured PASS:/FAIL:/SUMMARY: stdout protocol per MEM001.
