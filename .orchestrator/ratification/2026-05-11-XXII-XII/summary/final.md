### Systemic Contradictions

- **Governance layer sequencing without explicit dependency declaration**
  - **Manifests in**: Resolved Contradiction 1 (SOURCE A vs. SOURCE B pathway requirements), Resolved Contradiction 3 (Tier 2 eligibility as prior question to internal Distinctness check), Remaining Dispute 3 (membership basis argument must address SOURCE B's Purpose clause before orchestrator's internal Inclusion Criteria fires), Resolved Contradiction 2 (VIII disposition sequenced after membership basis).
  - **Root cause**: The proposal's Refresh block consulted SOURCE A's pathway taxonomy (conversus-oss CONSTITUTION.md) to validate the three-deliberation pattern and orchestrator's internal constitution to validate the inheritance shape, but did not consult SOURCE B's Purpose clause, cross-tier weakening prohibition, or meta-arbiter requirement until agents surfaced these gaps. Each governance layer has its own prerequisites; the proposal did not document the dependency order between them.
  - **Implication for spec**: The Refresh block should include an explicit governance-layer dependency tree before specifying the ratification path: (1) SOURCE B Purpose clause eligibility → (2) Tier 2 membership basis declaration → (3) orchestrator's internal Distinctness test (Criterion 3) against Principle VIII → (4) clause-by-clause mapping content → (5) CONFORMANCE.md row status labels. Any recommendation or deliverable that depends on a lower-numbered step cannot be specified without that step's output. The current Refresh block describes the ratification path without naming these dependencies, which produced most of the dangerous contradictions in this deliberation.

- **Evidence-completeness asymmetry between XII and XXII**
  - **Manifests in**: Resolved Contradiction 5 (XXII scripts absent vs. XII scripts on disk), Remaining Dispute 1 (clause-mapping timing is harder to resolve for XXII than for XII because XXII's substantive content depends on absent scripts), T-2 and S-2 convergence (both require a two-part gate for XXII that XII does not need).
  - **Root cause**: The proposal's Refresh block declared the XXII verification scripts "still ship" without specifying a delivery gate, while the XII evidence (check-dead-infra.sh, test-dead-infra-knobs.sh) had already landed as part of the Tier C alignment sweep. This created asymmetric certainty: agents could ground XII analysis in observable artifacts; XXII analysis required reasoning about absent files under a claim ("still ship") that turned out to be false.
  - **Implication for spec**: The Refresh block should add a "pre-ratification prerequisites" section separate from the "ratification path" section, with two rows: one for XII (evidence confirmed on disk; status: SATISFIED prerequisite) and one for XXII (three scripts not on disk; status: REQUIRED before deliberation). The ratification path section should reference these prerequisites as gates rather than assuming all evidence exists. This structural separation prevents future ratifications from conflating "the principle says these scripts should exist" with "these scripts do exist."

- **Scope boundary indeterminacy as a cascade dependency**
  - **Manifests in**: S-3 (XII clause mapping contingent on VIII disposition), S-5/T-4 convergence on three-bucket structure (but bucket boundaries depend on scope decisions not yet made), TN-3 dispute (what can the clause-mapping table contain before VIII disposition is resolved?), SN-1 (VIII disposition is a prerequisite, not a concurrent deliverable).
  - **Root cause**: The XII inheritance was added to the proposal after the Tier C alignment sweep "ported the linter" without checking whether Principle VIII already governed the same domain. Because the domain boundary between "orchestrator Principle VIII" and "Tier 2 XII inherited scope" was never drawn, every downstream question — which surfaces the three-bucket structure covers, which clauses require orchestrator analogs, which clauses require formal Relief — cannot be resolved until the boundary is declared.
  - **Implication for spec**: The Refresh block should require a "principle domain overlap check" as a step before the inheritance is declared, not after. For any proposed Tier 2 inheritance, the author should enumerate all existing orchestrator principles whose normative scope overlaps the inherited principle's normative body and declare the disposition (supersede, scope-boundary, or confirm no overlap) before the CONFORMANCE.md row is drafted. This check would have surfaced the VIII/XII overlap before the proposal reached deliberation, preventing the cascade of contingent recommendations.

- **CONFORMANCE.md drift from its reference document**
  - **Manifests in**: T-3/SN-2 (three principle names in the exclusion paragraph do not match the constitution they reference), Remaining Dispute 3 (the membership basis preamble does not exist; neither does the tracking policy row; neither does the per-clause mapping table), S-7 (independence from source Provisional status is undeclared).
  - **Root cause**: CONFORMANCE.md was authored incrementally as the project evolved, and principle names in the orchestrator constitution drifted after CONFORMANCE.md recorded them. The file has no automated lint check that its principle references match the constitution's actual names and no structural requirement that cross-referenced governance bodies (SOURCE B Purpose clause, orchestrator constitution) appear in its preamble before the rows that depend on them.
  - **Implication for spec**: CONFORMANCE.md should be treated as a machine-verifiable artifact, not a prose declaration. The ratification commit for this amendment should include a lint script (analogous to check-dead-infra.sh for XII) that extracts principle names from CONFORMANCE.md's exclusion list and checks them against the constitution's actual principle inventory. This lint script would have prevented the three label mismatches from persisting to the deliberation stage, and would serve as the mechanical verification mechanism for the CONFORMANCE.md accuracy invariant going forward.

- **Inheritance vs. extension ambiguity in the evidence framing**
  - **Manifests in**: S-5 (XII scope expansion declared as extension, not inheritance, for helper scripts and reference scaffolding), S-6 (XXII-XXV interaction applies to orchestrator's bash test suite, which is an orchestrator-specific adaptation of an inherited principle's cross-principle clause), S-3/TN-3 (clause mapping must distinguish inherited clauses from inapplicable ones from orchestrator-specific analogs), the Provisional status sections in both CONFORMANCE.md and the three-bucket structure.
  - **Root cause**: The proposal's Refresh block defines the inheritance shape as "evidence for satisfying inherited XXII/XII, not their own principle's enforcement mechanism" — but then declares orchestrator-specific surfaces (helper scripts, reference scaffolding) as in-scope for the XII inheritance. This conflates evidence for inherited requirements with extension of inherited requirements, creating a single framing that the three-bucket structure then has to decompose. The proposal lacks an operational definition of "inherit" that distinguishes the three categories before they appear in CONFORMANCE.md rows.
  - **Implication for spec**: The Refresh block should define three operational categories before any CONFORMANCE.md row is drafted: (a) Inherited and satisfied — normative clause from SOURCE B's body, orchestrator surface confirmed compliant; (b) Inherited and provisional — normative clause from SOURCE B's body, orchestrator surface not yet verified or linter not yet covering it; (c) Extended — orchestrator-specific addition that goes beyond SOURCE B's normative body, declared as an extension under XII's governing principle with a justification that it does not constitute a new principle. These three categories map directly to the converged three-bucket structure and make the CONFORMANCE.md row structure derive from the operational definitions rather than requiring ad hoc interpretation.
