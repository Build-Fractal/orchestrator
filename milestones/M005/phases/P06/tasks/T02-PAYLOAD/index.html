    Step 1: Create scripts/diagnostics/check-hashes.sh¶

    Create the file at scripts/diagnostics/check-hashes.sh:

    #!/usr/bin/env bash
# scripts/diagnostics/check-hashes.sh — Knowledge entry content_hash validator.
#
# Scans knowledge entry .md files for valid content_hash fields in YAML frontmatter.
# Valid format: content_hash: "sha256:<64 hex chars>" or content_hash: sha256:<64 hex chars>
#
# Usage: check-hashes.sh [--root <project-root>]
#
# Output: DOCTOR:HASHES status=<ok|warn> valid=N missing=N
#
# Bash 3.2 compatible.
set -eu

    Arguments: - --root <project-root> — defaults to PROJECT_ROOT env var or two levels up from script

    Logic: 1. Find knowledge entry files: look for .md files under <root>/.specify/orchestrator/knowledge/ and <root>/.specify/knowledge/. These files should have YAML frontmatter (delimited by ---).

    1. For each .md file found:
    2. Extract the YAML frontmatter (content between the first --- and the second ---)
    3. Look for a line matching content_hash: in the frontmatter
    4. If found, validate that the value matches sha256:[a-f0-9]{64} (with optional surrounding quotes)

    5. If not found or malformed, count as "missing"

    6. Count valid vs missing. If no knowledge entries exist, report status=ok valid=0 missing=0 (vacuously true).

    7. Output: DOCTOR:HASHES status=<ok|warn> valid=N missing=N

    8. If status=warn, list each file with missing/malformed hash prefixed with MISSING:.

    9. Exit 0 on ok, exit 1 on warn.

    Make executable: chmod +x scripts/diagnostics/check-hashes.sh

    Arguments: - --root <project-root> — defaults to PROJECT_ROOT env var or two levels up from script - --jsonl <file> — specific JSONL file to check. If not provided, scans all execution-log.jsonl files under .specify/orchestrator/milestones/

    Logic: 1. Collect JSONL files: if --jsonl provided, use that file. Otherwise find all execution-log.jsonl files under <root>/.specify/orchestrator/milestones/.

    1. For each JSONL file, read each line (each line is a JSON object).

    2. For each line, check if it contains the string "run_id" (simple string match — sufficient for JSONL where keys are always quoted). If present, count as with_id. If absent, count as without_id.

    3. If no JSONL entries exist, report status=ok with_id=0 without_id=0.

    4. Output: DOCTOR:RUNIDS status=<ok|warn> with_id=N without_id=N

    5. The status is ok if without_id=0, warn otherwise. Note: legacy entries without run_id are expected in older milestones, so this is advisory.

    6. If status=warn, report the count and which JSONL files contributed entries without run_id.

    7. Exit 0 on ok, exit 1 on warn.

    Make executable: chmod +x scripts/diagnostics/check-run-ids.sh
