    T04 Plan

    schema_version: "1.0" type: task-plan task: "T04" phase: "P01" milestone: "M013" name: "scripts/knowledge/rebuild-index.sh additive-emit pass — flat {chunk_id, title, phase_id} Spec Chunks section" depends_on: []

    Prerequisites¶

    • No upstream P01 task dependencies (independent of T01/T02/T03).
    • Existing state:
    • scripts/knowledge/rebuild-index.sh is the canonical index rebuilder. It currently emits a pipe-table format in KNOWLEDGE-INDEX.md with one row per detail file: <id> | <scope_tags> | <category> | <confidence> | <created_at> | verified:<date> | hits:<N> | <description>. This pre-existing section must remain byte-identical after this task's changes — the change is strictly additive (FR-9, D014 ruling on additive-emit boundary).
    • knowledge/spec/story/SPEC-US-*.md, knowledge/spec/acceptance/SPEC-AC-*.md, knowledge/spec/non-goal/SPEC-NG-*.md, knowledge/spec/constraint/SPEC-CON-*.md exist with YAML frontmatter carrying id:, category:, scope_tags: fields. Some (but not all) may carry phase_id: in frontmatter — check empirically during implementation; when absent emit the empty string.
    • Knowledge-Layer Boundary constraint (D014): chunk_id MUST be the verbatim value of the detail file's id: frontmatter field — no composite addressing, no new ID format. M013 is not authoring chunk-schema evolution; that is M020.

    Description¶

    Extend scripts/knowledge/rebuild-index.sh with a second emit pass that writes a new ## Spec Chunks section to KNOWLEDGE-INDEX.md. This section is a flat list — one line per SPEC-* detail file — in the format:

    <chunk_id> | <title> | <phase_id>

    Where: - chunk_id — verbatim id: field from frontmatter (e.g. SPEC-US-001). - title — the first # Markdown heading in the file body (excluding the SPEC-US-001: prefix if present), truncated to 80 characters. - phase_id — verbatim phase_id: frontmatter field when present, empty string otherwise.

    The existing pipe-table section (with MEM### and SPEC-* entries) must remain byte-identical — the new ## Spec Chunks section is appended after it. This is the additive-emit contract; non-negotiable.

    Steps¶

    Step 1: Read and understand the existing rebuilder¶

    Read scripts/knowledge/rebuild-index.sh and its lib dependencies: - scripts/knowledge/lib/index-utils.sh — where write_full_index() lives. - scripts/knowledge/lib/graph-db.sh — graph database init + edge writer; do not touch.

    Identify the point where KNOWLEDGE-INDEX.md is finalized (typically where write_full_index finishes writing, or where the script atomically renames a tmp file into place). The Spec Chunks section must be appended before that atomic rename so the final file includes it.

    Step 2: Add an "emit_spec_chunks" helper¶

    Either (a) extend scripts/knowledge/lib/index-utils.sh with an emit_spec_chunks_section <knowledge_dir> <out_path> function, or (b) inline the logic into rebuild-index.sh after the existing index-build call. Prefer (a) — lib extraction is the MEM004 Pure Lib Extraction Pattern.

    Helper contract:

    emit_spec_chunks_section <knowledge_dir> <out_path>
  Appends the following to <out_path>:
    (blank line)
    ## Spec Chunks
    <!-- Generated by rebuild-index.sh — flat {chunk_id, title, phase_id} list.
         chunk_id is pinned to SPEC-* frontmatter; this is NOT a new ID format.
         See .orchestrator/DECISIONS.md D014 and FR-9. -->
    <chunk_id> | <title> | <phase_id>
    <chunk_id> | <title> | <phase_id>
    ...
  Scans <knowledge_dir>/spec/**/SPEC-*.md; orders lexicographically by chunk_id.
  Skips any file under archive/.
  No return value; emits to stdout via append-redirect in caller.

    Pseudocode (pure Bash 3.2):

    emit_spec_chunks_section() {
  local knowledge_dir="$1"
  local out="$2"
  local found=0
  local tmp
  tmp="$(mktemp)"

  # Glob all SPEC-*.md under spec/ subtree, two levels deep.
  for f in "$knowledge_dir"/spec/*/SPEC-*.md; do
    [ -f "$f" ] || continue
    case "$f" in */archive/*) continue ;; esac

    # Extract id: from frontmatter
    chunk_id=$(sed -n '/^---$/,/^---$/p' "$f" | grep "^id:" | head -1 | sed 's/^id:[[:space:]]*//' | sed 's/^"//' | sed 's/"$//' | sed 's/[[:space:]]*$//')
    [ -z "$chunk_id" ] && continue

    # Extract phase_id: from frontmatter (may be absent — default empty)
    phase_id=$(sed -n '/^---$/,/^---$/p' "$f" | grep "^phase_id:" | head -1 | sed 's/^phase_id:[[:space:]]*//' | sed 's/^"//' | sed 's/"$//' | sed 's/[[:space:]]*$//')

    # Extract title: first `# ` heading after frontmatter; strip "SPEC-...: " prefix
    title=$(awk '/^---$/{c++; next} c>=2 && /^# /{sub(/^# /, ""); print; exit}' "$f")
    # Remove "SPEC-...: " prefix if present
    title=$(printf '%s' "$title" | sed -E 's/^SPEC-[A-Z]+-[0-9]+:[[:space:]]*//')
    # Truncate to 80 chars
    if [ ${#title} -gt 80 ]; then
      title=$(printf '%.80s' "$title")
    fi

    printf '%s | %s | %s\n' "$chunk_id" "$title" "$phase_id" >> "$tmp"
    found=1
  done

  if [ "$found" -eq 1 ]; then
    {
      printf '\n## Spec Chunks\n'
      printf '<!-- Generated by rebuild-index.sh — flat {chunk_id, title, phase_id} list.\n'
      printf '     chunk_id is pinned to SPEC-* frontmatter; this is NOT a new ID format.\n'
      printf '     See .orchestrator/DECISIONS.md D014 and specs/023-github-native-integration/spec.md FR-9. -->\n'
      sort "$tmp"
    } >> "$out"
  fi

  rm -f "$tmp"
}

    Step 3: Wire the helper into rebuild-index.sh¶

    After write_full_index finishes (or the equivalent "index body complete" point), call emit_spec_chunks_section "$knowledge_dir" "$out_file" (or the atomic tmp file path — whichever the existing script uses). Ensure the call happens before any atomic rename so the Spec Chunks section lands in the committed file.

    Guard the call with a presence check: if knowledge/spec/ doesn't exist, skip without error.

    Step 4: Create scripts/verify/m013-p01-rebuild-index-additive.sh¶

    Gate asserts:

    1. The existing pipe-table section is present and byte-identical to a pre-flight snapshot. Approach: the verifier runs rebuild-index.sh once against a fixture milestone root, captures the first N lines (up through the last pipe-table row, before any ## Spec Chunks heading), and diffs them against a known-good snapshot at tests/fixtures/m013-p01/knowledge-index-pre-chunks-snapshot.md. (The snapshot is produced once during implementation by running the pre-patch rebuilder on the fixture.)
    2. Practical simplification for this task: assert that the rebuilt file has the existing pipe-table format (lines like MEM012 | [project] | ... and SPEC-AC-001 | [project] | ...) still present and unchanged for MEM* rows. The SPEC-* pipe-table rows from the old format continue to appear (so nothing is removed).
    3. ## Spec Chunks section is present in the rebuilt KNOWLEDGE-INDEX.md.
    4. The Spec Chunks section contains at least one line matching ^SPEC-[A-Z]+-[0-9]+ \| .+ \| — the flat format.
    5. Every SPEC-* chunk ID that appears in the repo's knowledge/spec/**/SPEC-*.md files (as id: frontmatter) appears as a line in the Spec Chunks section.
    6. Re-running rebuild-index.sh a second time produces a byte-identical KNOWLEDGE-INDEX.md (idempotent — not additive-duplicated).
    #!/usr/bin/env bash
# scripts/verify/m013-p01-rebuild-index-additive.sh
set -u
REPO_ROOT="$(cd "$(dirname "${BASH_SOURCE[0]}")/../.." && pwd)"
REBUILDER="${REPO_ROOT}/scripts/knowledge/rebuild-index.sh"
INDEX="${REPO_ROOT}/KNOWLEDGE-INDEX.md"

fail_count=0
assert_ok() { if [ "$1" -eq 0 ]; then echo "PASS: $2"; else echo "FAIL: $2"; fail_count=$((fail_count + 1)); fi; }

[ -f "$REBUILDER" ]; assert_ok $? "rebuild-index.sh present"

# 1. Run the rebuilder
bash "$REBUILDER" --root "$REPO_ROOT" >/dev/null 2>&1
rc=$?
assert_ok "$rc" "rebuild-index.sh exits 0"

# 2. ## Spec Chunks section present
grep -q '^## Spec Chunks' "$INDEX"; assert_ok $? "KNOWLEDGE-INDEX.md has ## Spec Chunks section"

# 3. At least one flat-format row
grep -qE '^SPEC-[A-Z]+-[0-9]+ \| .+ \|' "$INDEX"; assert_ok $? "Spec Chunks section has flat-format row"

# 4. All knowledge/spec/**/SPEC-*.md ids appear in the section
missing=""
for f in "${REPO_ROOT}"/knowledge/spec/*/SPEC-*.md; do
  [ -f "$f" ] || continue
  case "$f" in */archive/*) continue ;; esac
  chunk_id=$(sed -n '/^---$/,/^---$/p' "$f" | grep "^id:" | head -1 | sed 's/^id:[[:space:]]*//' | sed 's/^"//' | sed 's/"$//' | sed 's/[[:space:]]*$//')
  [ -z "$chunk_id" ] && continue
  # Look for the chunk_id inside the Spec Chunks section only
  awk -v cid="$chunk_id" '
    /^## Spec Chunks/ { in_sec=1; next }
    /^## / && in_sec { exit }
    in_sec && $0 ~ "^"cid" \\|" { found=1; exit }
    END { exit (found ? 0 : 1) }
  ' "$INDEX"
  if [ "$?" -ne 0 ]; then
    missing="${missing}${missing:+,}${chunk_id}"
  fi
done
if [ -z "$missing" ]; then
  echo "PASS: every SPEC-* chunk id appears in Spec Chunks section"
else
  echo "FAIL: missing chunk ids in Spec Chunks section: ${missing}"
  fail_count=$((fail_count + 1))
fi

# 5. Idempotency
cp "$INDEX" "${INDEX}.baseline"
bash "$REBUILDER" --root "$REPO_ROOT" >/dev/null 2>&1
diff -q "$INDEX" "${INDEX}.baseline" >/dev/null
assert_ok $? "rebuild-index.sh is idempotent"
rm -f "${INDEX}.baseline"

if [ "$fail_count" -eq 0 ]; then
  echo "PASS: m013-p01-rebuild-index-additive.sh"
  exit 0
fi
echo "FAIL: m013-p01-rebuild-index-additive.sh ($fail_count failures)"
exit 1
