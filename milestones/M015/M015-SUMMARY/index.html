    Milestone Rollup¶

    The cutover happened now because M008 made standalone operation possible (multi-runtime packaging, adaptive intensity, backend-agnostic dispatch, 5-rule state-root resolver, orchestrator:init onboarding) and because M009 launch readiness required a clean narrative: an onboarding user coming to the project repo cannot find an extension.yml, nine /speckit.* project-owned slash commands, a .specify/scripts/bash/ host tree, or install docs that still say "copy the extension manifest" — any one of those would undermine the standalone story on first contact. M007's no-graceful-degradation principle governed the posture: hard-delete, no legacy/ rename, no compat shim, no dual code paths.

    The keep-vs-remove bucket decision followed a simple line. Out: extension manifest, dogfooded spec-kit slash commands, spec-kit-host helper scripts and templates, and the resolver bridge rule that still recognized .specify/orchestrator/ as a live state root. In: migration adapters (scripts/migrate/adapters/speckit.sh, scripts/state/detect-speckit.sh, scripts/dispatch/adapters/format/speckit.sh, commands/migrate.md) — spec-kit remains supported as a migration source forever, just not as a runtime host.     Key Decisions¶

    • Hard-delete discipline (M007 governance): git rm for tracked files; no legacy/ rename, no compat shim, no feature flag; verify scripts use file-absence assertions. Applied uniformly across P01 deletions and the P02 resolver bridge removal.
    • FR-013 migration-adapter preservation treated as orthogonal to host removal: scripts/migrate/, scripts/state/detect-speckit.sh, scripts/dispatch/adapters/format/speckit.sh, and commands/migrate.md were preserved verbatim — verified via empty git diff --stat on the exempt paths at P01 and P02 close.
    • Resolver reduction is a deletion, not a gating: the 5-rule resolver became a 4-rule resolver by outright deletion of the .specify/orchestrator/ bridge (Rule 4); the former Rule 5 was renumbered to Rule 4. No feature flag, no env-var escape hatch.
    • D003 — state_root: removal from .orchestrator/config.yml: the preserved state_root: ".orchestrator" line conflicted with Rule 3 directory existence (Rule 2 would win before Rule 3 fired). The line was removed; a commented example remains. Config is an override mechanism, not a canonical-location declaration.
    • P03 ALLOW_P03_DOCS sealed with never-match sentinel: after the docs graduated from transitional tolerance, the allow-list regex body was replaced with __P03_COMPLETE_NEVER_MATCH__ — converting the temporary accommodation into a permanent regression guard. Any future accidental reintroduction of a legacy path in those docs now surfaces as a real FAIL.
    • P04 clean-clone simulation uses working-tree tar, not git archive HEAD: deletions still live only in the working tree pre-commit (759 pending changes at P04 execution time), so git archive HEAD would have captured the pre-cutover tree. Working-tree tar with explicit fixture-path exclusions (tests/fixtures/) gave the true post-cutover shape.
    • P04/T02 migration-adapter invocation adapted inline: scripts/migrate/migrate.sh exposes --path/--output (not the --source/--target shape drafted in the plan); the constitution last-mile copy (.specify/memory/constitution.md → .orchestrator/memory/constitution.md) was materialized in-transcript since the adapter extracts to intermediate .dat format rather than directly producing a .orchestrator/ tree. Both adaptations were documented inline in the evidence transcript.
    • P01 opportunistic preflight fix: the evaluate-preflight.sh argument-passing bug (missing --project-root flag to generate-permissions.sh / write-permissions.sh) was patched in the same edit pass as the host-removal work, since the T03 author was already touching that code path. T03's planned Step 1 became a no-op; the required verify-script creation still happened.
    • P04 migration fixture is built deterministically by a script per run: tests/fixtures/m015-p04-speckit-migration/build-fixture.sh constructs the spec-kit-shaped fixture at test time rather than committing a populated tree — hermetic, deterministic, no drift.

    Patterns Established¶

    • Pre-change gate scaffolding (validation-as-task, MEM011): write verify scripts before the changes they assert, so every downstream task has an immediate pass/fail signal. Applied in every M015 phase — P01 removal gates, P02 migration gates, P03 reframe gates, P04 validation gates — all authored in each phase's T01 and expected to FAIL pre-change / PASS post-change.
    • Snapshot-based immutability check: capture at "first ## [" pre-edit, verify starting at "second ## [" post-edit; handles prepend-only append patterns (new CHANGELOG entry prepended above historical tail) without re-flagging the historical content as modified.
    • Seal-by-sentinel allow-list retirement: replace the regex body with __NAME_NEVER_MATCH__ when a transitional tolerance has served its purpose. Keeps the negated-grep syntax valid while tolerating nothing — converts the former accommodation into a permanent regression guard.
    • Hard-delete cutover with verify-script gating: for tracked files, git rm and assert file-absence in a dedicated verify script. No rename, no archive, no compat shim. The verify script is the durable guarantee against regression.
