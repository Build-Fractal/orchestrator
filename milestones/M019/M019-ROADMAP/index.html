    Cross-Cutting Concerns¶

    • Goodhart pairing (cost + quality together) — P01. Every unit_close record carries both a cost block and a quality block. Schema validator (scripts/verify/m019-schema.sh) rejects records missing either. Pairing happens at emission time, not at rollup time, so Tier 2 cannot accidentally optimize cost in isolation.

    • Zero-token instrumentation — P00, P01. P01 emitter writes the payload_breakdown after payload assembly, outside the agent's context. P00 must not introduce instrumentation prose into the payload itself. SC-6 and scripts/verify/m019-p01-zero-token-growth.sh enforce this — payload byte size before and after instrumentation must be identical.

    • Schema additivity for Tier 2/3 forward compat — P01. The source: "estimate" | "runtime" enum, granularity: "task" | "phase" | "milestone" enum, and record_type discriminator are reserved at Tier 1 so Tier 3 backend-actuals adapters land additively. No Tier 1 record-writer needs modification when Tier 3 ships its adapters/backend/*/report-usage.sh emitters. SC-4 + scripts/verify/m019-p01-source-enum.sh enforce.

    • Pre-M019 log-consumer additivity — P01. New fields are additive only; existing fields (duration_s, outcome, verification_result, attempt, unitId) keep current semantics + positions. scripts/state/derive-phase.sh and other current consumers must not break against either pre-M019 or M019-emitted logs. SC-10 + scripts/verify/m019-p01-additive-compat.sh.

    • P00→P01 hard ordering (SC-12) — P00, P01. No Tier 1 emitter record may be written to any post-M011 milestone log until P00's verify suite is green. Enforced by scripts/verify/m019-p01-no-pre-p00-emission.sh (P01 gate that fails if any emitter record predates P00 SUMMARY's completed_at). Backfilling adapted records after the fact is impossible — the dispatches already ran.

    • Bash 3.2 compatibility (Constitution VIII) — P00, P01. No declare -A, mapfile, ${var^^}, <(...), &>. Each phase ships a m019-<phase>-bash32-compat.sh gate scanning all touched/created .sh files. P00 establishes the pattern for P01.

    • No compound bash in agent-facing content (Constitution XV + M016/M021 anti-pattern linter) — P00. P00 template adaptations are agent-facing — must comply with M021 hook's 10-pattern matrix. P01 emitter code is verification-script-internal (MEM004 carve-out — pipes/$()/awk allowed). SC-9 + the existing scripts/verify/anti-pattern-lint.sh (must continue to exit 0).

    • P00 strictly dispatch-facing — P00. P00 touches templates whose output renders into payloads, recipe ordering, and intensity-gate prompt nudges. No drift into commands/, references/, docs/, README.md, or constitution edits. Boundary map enforces by listing only dispatch-facing produces.

    • No regression of existing behavior (SC-13) — P00. All tests/test-s01.sh..tests/test-s07.sh suites, the M021 P04 phase-suite, and scripts/verify/anti-pattern-lint.sh must continue to PASS unchanged against adapted templates. scripts/verify/m019-p00-no-regression.sh wraps the full suite as P00's load-bearing regression gate.

    • AD-7 settings.json additive-merge fix — P00. The evaluate-preflight.sh overwrite that strips the M021 hook + widened allow-list on every re-run is fixed inside P00 via a // generated:start / // generated:end sentinel pair in scripts/lifecycle/write-permissions.sh. Without this fix, any future evaluate re-run breaks zero-prompt baseline; with it, re-runs are idempotent. Verified by scripts/verify/m019-p00-evaluate-preflight-additivity.sh.

    • Scope discipline against Tier 2/3 creep (D009) — P00, P01. Non-Goals list is long: no orchestrator:cost, no rollup script, no efficiency footer, no anomaly checks, no backend-actuals adapters, no UI. Both phase boundary maps must produce zero items in those categories; verification rejects any drift.

    Dependency Graph¶

    P00 ──→ P01

    Strict linear ordering. SC-12 makes the P00→P01 edge a hard gate, not a soft preference.

    Execution Order¶

    1. P00 — Opus 4.7 Baseline Adaptation (no dependencies, executes first). High risk because adaptation cuts across dispatch + autonomy + templates and the regression-safety constraint (SC-13) is unforgiving — any test suite fail on adapted templates blocks the milestone.
    2. P01 — Tier 1 Emitter (depends on P00; cannot start until scripts/verify/m019-p00-phase-suite.sh is green). Medium risk because the schema decisions are well-specified and the emitter surface area is narrow (3 records × 3 boundary points), but the pre-M019 consumer additivity constraint (SC-10) and zero-token growth (SC-6) leave little room for error.

    No parallelization possible — only two phases, strictly sequential per the dependency graph.
