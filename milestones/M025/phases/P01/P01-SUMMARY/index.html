    P01 — Installer coexistence: hook-config schema + merge-not-overwrite + reversibility¶

    P01 remediates the M013/P04/T04 regression in one linear 4-task sweep. T01 rewrites the Claude Code runtime adapter's --hook-config emitter to produce real CC schema. T02 replaces the unconditional printf > settings.json overwrite with a scripts/util/settings-merge.sh deep-merge helper that preserves user-authored siblings and supports --uninstall via inline _orchestrator_managed: true tagging. T03 pins the fixture tree and the full gate suite. T04 lands documentation, knowledge entries, and the dual-write to Recent Changes. Phase-suite closes green: pass=10 fail=0. Total commits: 4bea909 → fe2a4d8 → f2a9585 → 1824b28 (preceded by scaffolding commit 17a2592).

    What was built¶

    T01 — Hook-config valid CC schema + event mapping (4bea909). scripts/dispatch/adapters/runtime/claude-code.sh --hook-config rewritten: single-quoted heredoc emits {"hooks": {"Stop": [...], "PreToolUse": [{"matcher": "Bash", ...}]}} with every leaf carrying _orchestrator_managed: true. Four orchestrator events (before_tasks, after_tasks, before_implement, after_implement) documented as deferrals with TODO(M025+) markers in an inline comment block. HOME guard added for adapter convention parity with --register. --probe and --register modes untouched byte-identically. Gate: m025-p01-hook-schema.sh (8 assertions; python3 JSON validation + 4 TODO-marker grep).

    T02 — Merge-not-overwrite installer + --uninstall flag (fe2a4d8). scripts/util/settings-merge.sh (333 lines) implements merge and uninstall subcommands with python3 as the JSON engine (jq-optional); temp-file-then-rename throughout; malformed target JSON → exit 4 with no write. Merge algorithm preserves every non-orchestrator top-level key byte-identically, deep-merges hooks.<event>[] arrays, and skips orchestrator entries whose command already exists under a managed-tagged object (idempotency guard; --force bypasses). Uninstall cascades: empty wrapper → drop; empty event array → drop key; empty hooks → drop. install-claude-code.sh replaces its overwrite block with a call to the helper; adds --uninstall flag short-circuit; --force passes through as idempotency-guard bypass. Gates: m025-p01-merge-preservation.sh (2), m025-p01-idempotency.sh (3). T01 regression unchanged.

    T03 — Fixture tree + gate suite + phase-suite orchestrator (f2a9585). tests/fixtures/m025-p01/gsd-baseline/settings.json (13 lines; $schema + statusLine + hooks.SessionStart + hooks.PostToolUse + permissions). expected-post-install.json captured from a real merge run (not hand-authored — canonicalization via python3 json.dumps(indent=2, sort_keys=True) would defeat manual capture). expected-post-uninstall.sha256 pinned from a round-trip run. Seven new gates: coexistence (3), uninstall-reversibility (5, dual-assert pinned-sha + structural baseline equivalence), runtime-scope-guard (8, pinned-sha on 4 sibling-runtime files + negative-grep for M025 markers), bash32-compat (42 assertions across 11 P01 .sh files, comment-line stripping before forbidden-token grep), docs (6, awaits T04), knowledge-entries (3, awaits T04), recent-changes (2, passes immediately via specify-time fragment match).     Decisions register updates¶

    • #Q-1 locked: event-mapping policy — post_verify → Stop (terminal; command orchestrator-post-verify); before_commit → PreToolUse + matcher Bash (command-regex git commit lives in the wrapper, not the matcher, because CC's matcher is tool-name only); four orchestrator events (before_tasks, after_tasks, before_implement, after_implement) deferred with TODO(M025+) markers. Revisit if Claude Code gains task-start / task-end / implement-start / implement-end events.
    • #Q-2 locked: tagging shape — inline _orchestrator_managed: true on each inserted hook leaf. No sidecar manifest. Rationale: self-contained (uninstall is a one-filter operation); CC lenient about unknown keys (no schema-validation rejection); sidecar drift was the larger pragmatic risk.
    • FR-8 byte-identity nuance — the spec promised pre-install-vs-post-uninstall byte-identity. Canonicalization via python3 json.dumps(indent=2, sort_keys=True) in the merge helper means post-uninstall is structurally equivalent to baseline but not byte-identical. Gate pins the post-roundtrip sha256 AND asserts structural equivalence to baseline — preserves FR-8 intent ("uninstalling restores the file") without requiring a byte-identity that canonicalization makes impossible. Candidate for a DECISIONS.md D-entry if this pattern recurs.
    • python3-for-awk-fallback — the spec's CON-2 committed to "awk/sed fallback" for jq-optional environments. Substituted python3 (already a de-facto baseline in scripts/verify/m013-p04-*.sh gates). Awk-based JSON deep-merge for bash 3.2 would dwarf the rest of T02. CON-2 updated in the pattern entry (MEM027) as "jq-optional with python3 fallback".

    Remaining known gaps (out of P01 scope)¶

    1. Config-removal marker — install-claude-code.sh --uninstall reports config-removed=0 always because nothing currently emits the _orchestrator_managed marker into .orchestrator/config.yml. Needs a follow-up: either write the marker at install time or relax the --uninstall contract to leave config.yml alone entirely. Low-urgency.
    2. Codex/Cursor parity — FR-9 intentionally scopes to Claude Code. Codex and Cursor installers don't write $HOME/.claude/settings.json, so coexistence isn't a live issue there today. Parity lands if/when those runtimes gain user-scope config paths worth merging (M010 fast-follow candidate).
    3. Spec path vs actual gate path — spec says tests/m025-p01-*.sh; gates live at scripts/verify/m025-p01-*.sh. Functional-equivalent (phase-suite runs them), but the SC-1..SC-6 prose is cosmetically off. Not worth a spec amendment; future milestones should align on scripts/verify/ from the start.
