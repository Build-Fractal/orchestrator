# Feature Specification: 027-conversus-oss-migration

**Feature Branch**: `027-conversus-oss-migration`
**Created**: 2026-04-23
**Status**: Draft
**Milestone**: M026
**Input**: User description: "Migrate the orchestrator's default Conversus integration from the paid build at ~/Sites/conversus to the open-source build at ~/Sites/conversus-oss, while preserving an operator-controlled escape hatch so paid-only features remain reachable from the adapter layer. Scope: (a) parity audit of the orchestrator's consumption surface (conversus.sh adapter CLI invocations, conversus-synth.py config shape, output-tree + linter.output_contract schema, CLI flags, env vars, exit codes) against both builds; (b) resolver-order update in scripts/dispatch/adapters/tool/conversus.sh so $HOME/Sites/conversus-oss is the user-local default with $HOME/Sites/conversus reachable via opt-in; (c) clear diagnostic when a caller names a paid-only feature on an OSS install; (d) preservation of the D019 TODO pre-flight, --strict flag, 0/1/2 exit-code contract, stub-mode fixtures, and CONVERSUS_STUB / CONVERSUS_STRICT / CONVERSUS_HOME / CONVERSUS_PROVIDER env-var semantics; (e) documentation updates across commands/conversus-gate.md, commands/ingest.md, commands/specify.md, docs/ingesting-arbitrary-specs.md, and references/ so resolver order + paid-escape-hatch shape are discoverable; (f) test updates to tests/test-conversus-adapter-shim.sh covering both OSS and paid binary paths with CONVERSUS_INTEGRATION=1 gating. Non-goals: do not change the adapter's 0/1/2 exit-code contract or preset shape; do not modify either conversus repo; do not re-open spec 025 (M020) or spec 026 (M014 three-pass shell impl) scope; do not implement MCP-renderer escape hatch (that is M023 scope). Must respect in-flight M014 three-pass shell (spec 026) and M020 knowledge-layer pressure-test re-run dependency on upstream PRs #28/#29."

## Problem Statement

The orchestrator's Conversus integration — shipped as the reusable tool adapter at `scripts/dispatch/adapters/tool/conversus.sh` under M011/P07 and reused at M013 UAT PR gate, M014 `orchestrator:specify` Pass 3, and future M018/M023/M024 gate points per D007/D014/D017 — is hard-coded in its binary-resolution path to prefer `$HOME/Sites/conversus`, which is the paid Conversus build. The operator has installed the Open-Source Conversus build at `$HOME/Sites/conversus-oss` and wants the orchestrator's default to flip so that fresh installs and autonomous runs pick up OSS without any per-caller configuration. Simultaneously, a handful of load-bearing surfaces (debugging a paid regression, invoking paid-only presets or provider paths that OSS hasn't yet caught up to, or running a regression test against a specific paid-build revision) still need paid reachability, so the migration cannot be a clean cutover — it must land as a default-flip with a first-class escape hatch.

Three concrete pain-points follow from the current resolver-order shape. **First**, the resolver's `~/Sites/conversus` fallback (adapter `conversus.sh:74`) means every operator who clones the OSS build into `~/Sites/conversus-oss` still has their orchestrator pick up the paid build if present on disk, defeating the point of OSS adoption and silently coupling dogfood runs to whichever build the operator last installed. **Second**, there is no operator-facing knob that distinguishes "I want OSS by default" from "I want paid by default" — the only knob today is `CONVERSUS_HOME`, which is an absolute override and doesn't express edition intent. Callers that need a paid-only feature on an OSS-default system have to know the exact `CONVERSUS_HOME` path and set it per invocation, which is both undiscoverable and easy to forget. **Third**, the current adapter emits no diagnostic when a caller invokes a preset or provider that requires paid-only upstream plumbing — an OSS install that doesn't ship `linter.output_contract` with the exact schema the adapter parses, or an OSS build that lacks the `conversus login anthropic` OAuth subscription path, or a future paid-only mode — will fail opaquely at `conversus run` time with no actionable pointer toward the escape hatch.

The minimum surface that fixes all three: **(a)** extend `conversus.sh` resolver order to prefer `$HOME/Sites/conversus-oss/bin/conversus` (new user-local default) over `$HOME/Sites/conversus/bin/conversus` (now the escape hatch), leave `CONVERSUS_HOME` as the absolute override, and add a `CONVERSUS_EDITION=oss|paid` env var that flips the relative resolver preference between the two user-local paths; **(b)** add one edition-aware diagnostic the adapter prints when the resolved binary appears to be OSS but the invocation names a paid-only surface (detected by preset metadata or provider selection, deferred to plan-phase for mechanical detection rules); **(c)** preserve every other adapter invariant byte-identically — 0/1/2 exit codes, `--strict` flag semantics, D019 TODO pre-flight, stub-mode fixture shape, all existing env vars including `CONVERSUS_STUB`/`CONVERSUS_STRICT`/`CONVERSUS_HOME`/`CONVERSUS_PROVIDER`/`CONVERSUS_RUN_OUTPUT_DIR`/`CONVERSUS_GATE_TODO_THRESHOLD`/`CONVERSUS_GATE_SKIP_TODO_CHECK`; **(d)** update six documentation surfaces (`commands/conversus-gate.md`, `commands/ingest.md`, `commands/specify.md`, `docs/ingesting-arbitrary-specs.md`, `references/github-integration.md`, `references/spec-management.md`) so the new resolver order and escape-hatch shape are discoverable at the same reading paths operators already use; **(e)** extend the integration test to run against both builds under `CONVERSUS_INTEGRATION=1`, keeping the stub-mode path unchanged.

This feature explicitly does not attempt: (1) modifications to either `~/Sites/conversus` or `~/Sites/conversus-oss` — both repos are read-only from this milestone's POV; (2) re-opening the 0/1/2 exit-code contract, the `--strict` flag semantics, the preset YAML shape, or the `conversus.yml` synthesis output shape (those are cross-cutting contracts other milestones depend on); (3) re-opening spec 025's (M020 knowledge-layer) status of `Ready-for-discuss-gate-deferred` — this spec notes the cross-cut in Open Questions and defers scheduling decisions to discuss-finalize; (4) re-opening spec 026's (M014 three-pass shell) scope — this spec's implementation must land before or after spec 026's shell-impl but does not modify that spec's body; (5) implementing an MCP-renderer escape hatch for M023 Design Layer — that is M023 scope per D016; (6) a migration of the paid build's upstream PRs (#28 claude-code, #29 anthropic parallel-429) into the OSS build — those are upstream concerns to the operator, not the orchestrator's work; (7) automatic runtime detection of paid-feature usage at dispatch time — mechanical detection is deferred to plan-phase, with the minimum-viable diagnostic being edition + binary path logged at every `gate` invocation.

## User Scenarios & Testing *(mandatory)*

### Minimal Slice (Phase 1 Load-Bearing Scope)

The smallest coherent subset whose shipment closes the dogfood loop: **US-1 (resolver-order flip with OSS default) + US-2 (edition env var + paid escape hatch) + US-3 (parity audit + pass-through invariants test)**. Together they deliver an end-to-end path where a fresh install with both trees present picks up OSS by default, an operator sets `CONVERSUS_EDITION=paid` and gets the paid build, and the integration test confirms the 0/1/2 exit-code contract holds on both builds for the canonical `spec-pressure-test` + `normalize-fidelity` presets. US-4 (edition-aware diagnostics) and US-5 (documentation updates) depend on the slice and layer on afterward — discoverable surface is load-bearing for launch, but the dogfood loop closes without it.

### User Story 1 — Resolver-order flip with OSS as user-local default (Priority: P1)

An operator with both `$HOME/Sites/conversus-oss/bin/conversus` and `$HOME/Sites/conversus/bin/conversus` on disk, no `CONVERSUS_HOME` env var set, and no `CONVERSUS_EDITION` env var set, invokes any orchestrator command that reaches `scripts/dispatch/adapters/tool/conversus.sh` (e.g., `orchestrator:specify` at Full intensity on an above-threshold draft) and the adapter resolves the OSS binary. The operator can see the resolved path + edition in the adapter's diagnostic output and in the JSONL `conversus_gate_invocation` record.

**Why this priority**: this is the product ask — flip the default. Every other user story defends or documents this one. Without US-1, the migration has not happened.

**Independent Test**: under a hermetic scratch with both binaries present (real or symlinked), run `bash scripts/dispatch/adapters/tool/conversus.sh check` with no `CONVERSUS_HOME` / `CONVERSUS_EDITION` set; assert stdout reports `available=true` and `conversus_path=<...>/conversus-oss/bin/conversus`. Assert an adjacent `edition=oss` line is present in the diagnostic.

**Acceptance Scenarios**:

1. **Given** both `~/Sites/conversus-oss/bin/conversus` and `~/Sites/conversus/bin/conversus` exist, **When** the operator runs `bash scripts/dispatch/adapters/tool/conversus.sh check` with no edition-related env vars set, **Then** the resolved binary path ends in `conversus-oss/bin/conversus` and the output includes an `edition=oss` line.
2. **Given** only `~/Sites/conversus/bin/conversus` exists (no OSS install), **When** the operator runs `check`, **Then** the resolved binary path is `~/Sites/conversus/bin/conversus` and the output includes `edition=paid reason=oss-not-installed` so the fallback is visible.
3. **Given** neither binary exists, **When** the operator runs `check`, **Then** the output includes `available=false` exactly as today (no regression of the graceful-degradation path).

### User Story 2 — Edition env var + paid escape hatch (Priority: P1)

An operator working against a paid-only feature (e.g., reproducing a bug in the paid build's output-contract linter, or running a preset that names a paid-only provider path) sets `CONVERSUS_EDITION=paid` before invoking an orchestrator command that reaches the adapter. The adapter resolves `~/Sites/conversus/bin/conversus` (the paid build) even when the OSS build is also installed. `CONVERSUS_HOME` remains the absolute override and trumps `CONVERSUS_EDITION`.

**Why this priority**: the product ask explicitly requires an escape hatch. An operator with a legitimate paid-feature need should not have to uninstall OSS or construct a `CONVERSUS_HOME` path from memory. This is the surface that makes the default-flip safe to ship.

**Independent Test**: with both binaries installed, run `CONVERSUS_EDITION=paid bash scripts/dispatch/adapters/tool/conversus.sh check`; assert resolved path ends in `conversus/bin/conversus` (paid). Then set `CONVERSUS_HOME=/tmp/fake-home/bin/conversus` (a third path, does not exist) with `CONVERSUS_EDITION=paid`; assert resolver reports `available=false` (CONVERSUS_HOME trumps edition).

**Acceptance Scenarios**:

1. **Given** both binaries are installed and `CONVERSUS_EDITION=paid`, **When** the operator runs `check`, **Then** the resolved path is the paid binary and `edition=paid reason=env-override` is emitted.
2. **Given** both binaries are installed, `CONVERSUS_EDITION=oss`, and `CONVERSUS_HOME` points at a third existing binary, **When** the operator runs `check`, **Then** `CONVERSUS_HOME` wins (absolute override precedence unchanged).
3. **Given** `CONVERSUS_EDITION=paid` but only OSS is installed, **When** the operator runs `check`, **Then** the resolver reports `edition=oss reason=paid-requested-but-not-installed` with `available=true` so the operator sees the fallback explicitly rather than silently getting OSS.

### User Story 3 — Parity audit + byte-equivalent pass-through invariants (Priority: P1)

The migration ships with a parity matrix (captured in spec/plan-phase artifacts) and a regression test that asserts the adapter's caller-visible behavior — `gate` subcommand exit codes, `gate-result.md` frontmatter shape, stub-mode fixture path, TODO pre-flight semantics, `--strict` flag handling — is byte-equivalent on OSS and paid builds for the canonical `spec-pressure-test` and `normalize-fidelity` presets.

**Why this priority**: five production callers (`orchestrator:specify` Pass 3, `orchestrator:ingest` fidelity gate, M013 UAT PR gate, M011/P07 end-to-end test, M014/P04 three-way prompt) depend on the adapter's exit codes and output shape. If OSS diverges silently — a different `linter.output_contract` JSON schema, a different output-tree layout, a different provider flag — those callers break. The parity matrix + regression test are the two artifacts that prevent that from happening unnoticed.

**Independent Test**: extend `tests/test-conversus-adapter-shim.sh` so the existing `CONVERSUS_INTEGRATION=1` block runs twice — once with `CONVERSUS_EDITION=oss` and once with `CONVERSUS_EDITION=paid` — asserting identical exit codes and identical `verdict:` / `disputes:` / frontmatter keys in both outputs against a fixed artifact. The stub-mode path (unchanged) continues to run unconditionally.

**Acceptance Scenarios**:

1. **Given** both builds are installed, **When** the integration test runs with `CONVERSUS_EDITION=oss` and then with `CONVERSUS_EDITION=paid` against a fixture artifact, **Then** both runs produce the same exit code and the same frontmatter keys (verdict may differ in value — the contract is shape, not outcome).
2. **Given** only OSS is installed, **When** the test runs, **Then** the OSS branch passes and the paid branch reports a skip with `SKIP: paid build not installed` (not a fail).
3. **Given** the adapter's 0/1/2 exit-code contract is honored, **When** a caller handles BLOCK (exit 2), **Then** the handling is indistinguishable between OSS and paid invocations (no caller code change is required by the migration).

### User Story 4 — Edition-aware diagnostics for paid-only surface use (Priority: P2)

A caller invokes the adapter with a preset or provider selection that the orchestrator has identified as paid-only (mechanical detection rule deferred to plan-phase — minimum-viable rule is "preset declares `edition_required: paid` in frontmatter OR `CONVERSUS_PROVIDER=claude-code` pre-PR-#28"). When the resolved binary is OSS, the adapter prints an actionable diagnostic naming the paid-only surface, the escape-hatch env var, and the next-action suggestion.

**Why this priority**: diagnostic clarity is load-bearing for launch but not for dogfood. Without US-4, an OSS-install operator who hits a paid-only surface gets an opaque upstream error; with US-4 they get a pointer to `CONVERSUS_EDITION=paid`. US-4 is P2 because the dogfood loop closes on US-1+US-2+US-3 alone (operator can discover the escape hatch from docs); US-4 makes the surface polished.

**Independent Test**: author a fixture preset with `edition_required: paid` in its frontmatter (under `tests/fixtures/`) and run the adapter against it with the OSS binary resolved; assert stderr contains "paid-only surface" and "CONVERSUS_EDITION=paid" substrings, and exit code is 1 (adapter error — distinct from BLOCK).

**Acceptance Scenarios**:

1. **Given** a preset declares `edition_required: paid` in frontmatter, **When** the adapter is invoked with OSS resolved, **Then** the adapter exits 1 with a diagnostic naming the preset, the edition requirement, and the escape-hatch env var.
2. **Given** a preset has no `edition_required` field, **When** the adapter is invoked with either edition, **Then** the diagnostic is not emitted (backward-compatible).
3. **Given** a preset declares `edition_required: paid` and the adapter is invoked with paid resolved, **When** the preset runs, **Then** no diagnostic is emitted and the invocation proceeds.

### User Story 5 — Documentation updates across discoverable surfaces (Priority: P2)

The operator reads `commands/conversus-gate.md`, `commands/ingest.md`, `commands/specify.md`, `docs/ingesting-arbitrary-specs.md`, `references/github-integration.md`, or `references/spec-management.md` and discovers the new resolver order (OSS user-local default), the `CONVERSUS_EDITION` env var, and the paid escape-hatch shape. The existing resolver-order prose in those docs — which today says `$HOME/Sites/conversus/bin/conversus` is the user-local convention — is updated to reflect the new default.

**Why this priority**: documentation is the second-order surface that makes the migration land for external operators. P2 because the dogfood loop closes without it (the primary operator is the one who filed the migration), but launch-readiness requires it.

**Independent Test**: grep each of the six doc surfaces for `conversus-oss` and `CONVERSUS_EDITION` substrings; assert at least one hit per surface for each. Grep for the literal `$HOME/Sites/conversus/bin/conversus` — every hit that previously called this "the user-local default" must now call it "the paid escape-hatch".

**Acceptance Scenarios**:

1. **Given** the doc-update subtask is complete, **When** the operator greps `commands/conversus-gate.md` for `conversus-oss`, **Then** at least one hit names the new default and at least one hit names `CONVERSUS_EDITION`.
2. **Given** the update, **When** the operator reads `docs/ingesting-arbitrary-specs.md:178-186`, **Then** the resolver-order block names `conversus-oss` before `conversus` and explains the edition env var.
3. **Given** an existing doc that describes the 4-step resolver order, **When** the operator re-reads it post-migration, **Then** the 4-step order is updated in place (no net-new resolver documentation; revise, don't layer).

## Edge Cases

- **Both binaries missing**: resolver emits `available=false` exactly as today; graceful degradation unchanged. No new `edition=` line needed (edition is meaningless without a resolved binary).
- **Symlink farm**: operator has `~/Sites/conversus-oss` symlinked to `~/Sites/conversus` (single binary, two paths). Resolver treats them as equivalent — first path in order wins; no canonical-path resolution. Operators who symlink accept the behavioral coupling.
- **`CONVERSUS_HOME` points at an OSS install but `CONVERSUS_EDITION=paid` is set**: `CONVERSUS_HOME` trumps `CONVERSUS_EDITION`. The edition env var only affects the relative order of the two user-local paths; absolute override is absolute.
- **Edition-aware diagnostic fires against a preset without `edition_required` frontmatter**: never fires. Absence of the frontmatter field is treated as "no edition requirement" (backward-compatible with every existing preset under `templates/conversus-presets/`).
- **Pipx venv path drift** (`~/.local/pipx/venvs/conversus/bin/python` → `~/.local/pipx/venvs/conversus-oss/bin/python` or similar): the integration test's venv-python lookup (`tests/test-conversus-adapter-shim.sh:119-124`) must accept either location. Plan-phase decides whether to probe both or make it edition-aware.
- **`linter.output_contract` module missing on OSS** (upstream split, rename, or deferred work): detected at `conversus.sh:298` via the venv-python `python -m linter.output_contract` invocation. Adapter already handles rc != 0 by emitting `output parser failed` and exit 1. Migration does NOT silently hide this — it surfaces as an adapter error the operator can diagnose.
- **Operator-installed conversus at a non-standard path via `CONVERSUS_HOME`**: unchanged — `CONVERSUS_HOME` wins over edition resolution (tests cover this).

## Functional Requirements

- **FR-1 (resolver-order-flip)**: `scripts/dispatch/adapters/tool/conversus.sh` `_resolve_binary()` function must probe `$HOME/Sites/conversus-oss/bin/conversus` before `$HOME/Sites/conversus/bin/conversus` when neither `CONVERSUS_STUB=1` nor `CONVERSUS_HOME` is set. Emits `available=true conversus_path=<...> edition=oss|paid` on success. Satisfies US-1.
- **FR-2 (edition-env-var)**: `CONVERSUS_EDITION=oss|paid` reverses the default resolver preference between the two user-local paths. `oss` = default behavior; `paid` = probe `conversus/bin/conversus` first. Any other value falls back to default (with a stderr warning). `CONVERSUS_HOME` and `command -v conversus` both trump `CONVERSUS_EDITION` (precedence: STUB → HOME → PATH → EDITION-sensitive user-local probe). Satisfies US-2.
- **FR-3 (edition-line-in-check)**: `conversus.sh check` output includes a new `edition=<oss|paid|unknown> reason=<default|env-override|fallback|path|home|stub>` line alongside the existing `available=` and `conversus_path=` lines. `unknown` is used when the resolved binary is neither at the OSS nor paid canonical paths (e.g., resolved via `command -v conversus` or `CONVERSUS_HOME`). Satisfies US-1, US-2.
- **FR-4 (conversus_gate_invocation-edition)**: the JSONL record emitted at every `gate` invocation (via `scripts/integrations/github-common.sh emit_conversus_gate_record` and `scripts/specify/specify.sh:532`) gains an `edition` field alongside the existing `verdict`, `gate_id`, `spec_path`, `adapter_version`, `llm_calls`, `elapsed_ms`, `estimated_cost_usd`, `source` fields. Populated from the adapter's resolver. Value: `oss|paid|unknown`. Satisfies US-1, US-3 (observability for post-hoc diagnosis).
- **FR-5 (exit-code-contract-preserved)**: 0 (PASS or SKIPPED), 2 (BLOCK), 1 (adapter error) — byte-identical to today. No new exit codes; no changes to existing semantics. Satisfies US-3.
- **FR-6 (flag-and-env-var-preserved)**: `--strict`, `CONVERSUS_STUB`, `CONVERSUS_STUB_VERDICT`, `CONVERSUS_STRICT`, `CONVERSUS_HOME`, `CONVERSUS_PROVIDER`, `CONVERSUS_RUN_OUTPUT_DIR`, `CONVERSUS_GATE_TODO_THRESHOLD`, `CONVERSUS_GATE_SKIP_TODO_CHECK`, `CONVERSUS_INTEGRATION` — semantics unchanged. D019 TODO pre-flight unchanged. Stub-mode fixtures unchanged. Satisfies US-3.
- **FR-7 (gate-result-shape-preserved)**: `gate-result.md` frontmatter fields (`verdict`, `disputes`, `rationale`, `source_hash`, `preset`, `artifact`, `conversus_output_dir`, `conversus_config`) unchanged. Adapter may add optional fields under a `conversus_edition:` key but must not reorder or rename existing fields. Satisfies US-3.
- **FR-8 (parity-regression-test)**: `tests/test-conversus-adapter-shim.sh` gains a dual-edition harness gated on `CONVERSUS_INTEGRATION=1`. Runs the existing integration block twice (once per edition when both builds are installed; skips the absent edition cleanly with a `SKIP:` line). Asserts identical exit-code + frontmatter-key-set across both runs against the same fixture artifact. Stub-mode path untouched. Satisfies US-3.
- **FR-9 (parity-matrix-artifact)**: plan-phase produces `.orchestrator/milestones/M026/M026-CONVERSUS-PARITY.md` capturing every CLI flag, env var, config-schema key, output-tree path, and exit-code contract the orchestrator consumes, with a column per edition marked `verified: true|false`. Scratch parity note at `.orchestrator/scratch/conversus-oss-migration-parity.md` (shipped with this spec) is the pre-planning input; the plan-phase artifact is the authoritative close-out. Satisfies US-3 discoverability.
- **FR-10 (preset-edition_required-field)**: the `templates/conversus-presets/*.yml` frontmatter schema is extended with an optional `edition_required: paid` field. Presets with the field trigger US-4's diagnostic when run on OSS; presets without it behave identically to today. No existing presets gain the field as part of this migration — that's a per-preset authoring decision made by whoever authors a paid-dependent preset in the future. Satisfies US-4.
- **FR-11 (diagnostic-on-paid-only-surface)**: when `edition_required: paid` is present in the preset frontmatter and the resolved binary edition is `oss`, the adapter prints to stderr a line matching the regex `ERROR: preset '<name>' requires paid Conversus \(edition_required: paid\); resolved edition is oss\. Set CONVERSUS_EDITION=paid or install the paid build at \$HOME/Sites/conversus/bin/conversus\.` and exits 1. The diagnostic fires before any `conversus run` invocation — no upstream work is triggered. Satisfies US-4.
- **FR-12 (doc-surface-updates)**: six doc surfaces listed in the Problem Statement update their resolver-order prose in place. The M011-era `commands/conversus-gate.md:24-28` four-step resolver order is rewritten as a five-step order: STUB → HOME → PATH → OSS-user-local (new default) → paid-user-local (now escape hatch); the `CONVERSUS_EDITION` env var is documented as the user-local-order selector. Docs must grep-match `conversus-oss` and `CONVERSUS_EDITION`. Satisfies US-5.
- **FR-13 (knowledge-layer-entry)**: this milestone contributes at most two `knowledge/decisions/MEM*.md` entries (edition-resolution pattern, paid-escape-hatch pattern) at consolidate. No mutation of `knowledge/spec/**` chunks produced by spec 027's own ingest. The Knowledge-Layer Boundary section below names M020 as the owner of knowledge/** schema evolution — this milestone adds entries under its own decision namespace only. Satisfies principle VII (knowledge compounds) without crossing the M020 schema boundary.

## Success Criteria

- **SC-1 (oss-default-flip)**: with both binaries installed and no edition-related env vars, `bash scripts/dispatch/adapters/tool/conversus.sh check` stdout contains the exact substring `conversus-oss/bin/conversus` on the `conversus_path=` line AND contains the exact line `edition=oss`. Command exits 0.
- **SC-2 (paid-escape-hatch)**: with both binaries installed, `CONVERSUS_EDITION=paid bash scripts/dispatch/adapters/tool/conversus.sh check` stdout contains `conversus/bin/conversus` (and does NOT contain `conversus-oss`) on the `conversus_path=` line AND contains `edition=paid`. Command exits 0.
- **SC-3 (home-override-precedence)**: with any edition env var and a valid `CONVERSUS_HOME` pointing at a third path, `check` resolves to the `CONVERSUS_HOME` path (not the edition-preferred user-local path). Observable: `conversus_path=` matches the HOME path.
- **SC-4 (exit-code-regression)**: `bash tests/test-conversus-adapter-shim.sh` exits 0 on a tree where neither binary is installed (stub path only). With `CONVERSUS_INTEGRATION=1` and both builds installed, the test exits 0 and its output contains `PASS:` lines for both editions. With only one build installed, the absent-edition branch reports `SKIP:` not `FAIL:`.
- **SC-5 (jsonl-edition-field)**: after running `orchestrator:specify` at Full intensity on an above-threshold spec with `y` to the conversus pressure-test prompt, `grep '"edition":' .orchestrator/execution-log.jsonl | tail -n 1` returns a line whose value is `oss` or `paid` (never empty, never `unknown` on a canonically-installed system).
- **SC-6 (byte-equivalence-on-unchanged-surfaces)**: the integration test's frontmatter-key-set assertion (FR-8) lists every key the paid build produced BEFORE this migration. Post-migration, OSS produces the same key set (value equivalence is not asserted; shape is). Mechanically verified by a sorted-key diff with zero lines of output.
- **SC-7 (diagnostic-on-paid-only-preset)**: a test fixture preset with `edition_required: paid` frontmatter, invoked via the adapter on an OSS-resolved binary, produces stderr matching `paid-only.*CONVERSUS_EDITION=paid` (case-insensitive) and exits 1. Mechanically verified by a new test case in `tests/test-conversus-adapter-shim.sh`.
- **SC-8 (doc-discoverability)**: `grep -l 'conversus-oss\|CONVERSUS_EDITION' commands/conversus-gate.md commands/ingest.md commands/specify.md docs/ingesting-arbitrary-specs.md references/github-integration.md references/spec-management.md` reports all six files (not five, not seven).
- **SC-9 (parity-matrix-artifact-present)**: `.orchestrator/milestones/M026/M026-CONVERSUS-PARITY.md` exists at milestone close with at minimum these columns: `Surface`, `OSS`, `Paid`, `Verified`. Every row has a non-empty `Verified:` cell.
- **SC-10 (no-caller-code-change)**: `grep -rn 'conversus.sh gate\|conversus-synth.py\|conversus-preset' scripts/ commands/ tests/` post-migration reports the same file set as pre-migration (no callers relocated, no imports reshaped). The migration is resolver-local.
- **SC-11 (cross-cut-with-spec-026)**: spec 026's shell implementation of `orchestrator:specify` Pass 3 calls `conversus.sh gate --strict` and reads exit codes 0/1/2. Running spec 026's test harness (`tests/test-specify-*.sh` or equivalent) against an OSS-resolved adapter produces the same pass/fail signature as against a paid-resolved adapter (binary divergence across editions cannot re-shape spec 026's contract).
