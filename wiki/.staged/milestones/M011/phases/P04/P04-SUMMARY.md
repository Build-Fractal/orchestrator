P04 wires the spec knowledge ingested in P01-P03 into the dispatch pipeline: a task plan tagged `scope_tags: [spec/requirement/SPEC-FR-003]` now produces a dispatch payload whose `## Spec Context` section contains only SPEC-FR-003 plus its related acceptance/constraint chunks — not the full spec. Three tasks delivered the chain end-to-end:

T01 extended `scripts/dispatch/scope-filter.sh` with a new `--spec-scope-tags` ID-emission mode. The new `filter_spec_scope_tags` function parses `spec/<cat>/<SPEC-XX-NNN>` tokens, resolves each against `knowledge.db` (with a file-frontmatter fallback for sandbox testing), skips superseded tips (stderr `WARN:`) and non-goals (unless `--include-non-goals`), then unions 1-hop `relates_to` neighbors via `traverse-graph.sh`. Mode is self-sufficient — positional `<file> <scope>` args are bypassed via an `if -z "$SPEC_SCOPE_TAGS"` guard around the existing validation block. T03 later tightened Pass 2 to also drop non-goal / superseded graph neighbors, closing the AD-7 path that only the rich fixture exercised.

T02 added a recipe-driven `spec_context` section. `handle_spec_context` in `scripts/dispatch/lib/section-handlers.sh` reads task-plan frontmatter `scope_tags:`, filters to `spec/*` tokens, delegates resolution to T01's scope-filter, and walks the knowledge tree directly (one- and two-level) to emit chunk bodies — `resolve-entries.sh` only handles one-level layout and was locked by task scope. `templates/context-recipe.yaml` gained a `spec_context` entry at order 35 (compressible, filter: scope, cache_hint: semi-static). `build-context.sh`'s display helpers now know about `spec_context`, and the section-dispatch loop was rewritten to use staging files with mv-on-commit so the section omits entirely (manifest row + body) when the handler produces zero bytes — preserving the contiguous `s${idx}.txt` naming that the manifest assembler requires. A subtle crosscut: `build-context.sh` clobbers `PROJECT_ROOT` at startup, so the handler derives its knowledge root from the passed `orch_root` argument and re-exports `PROJECT_ROOT` on the scope-filter subprocess call.

T03 delivered the end-to-end demo-scenario script — a 13-entry fixture with 5 requirements (including a SPEC-FR-005-v1→v2 superseded chain), 3 acceptances, 2 constraints, a non-goal wired via `relates_to: [SPEC-FR-003]` to exercise the AD-7 graph-neighbor path, and a story — plus assertions verifying both the in-scope present set (SPEC-FR-003, SPEC-AC-007, SPEC-AC-008, SPEC-CON-001) and the 8-ID absent set. T03 also tightened `m011-p04-bash32-compat.sh` to scan `build-context.sh` and `section-handlers.sh` alongside `scope-filter.sh`. The engineered fixture caught a real bug: T01's Pass 2 was leaking the non-goal neighbor because it filtered only direct tags; T03 fixed it in T01 territory rather than papering over in the verify script.
