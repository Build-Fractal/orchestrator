T01 lands the Tier 1 microcompact stage of the M018 compression pipeline inside `scripts/dispatch/build-context.sh`. A new `_bc_apply_tier1` helper detects tool-result blocks above a configurable token threshold, persists their bodies to a SHA-256-keyed cache (`.orchestrator/cache/tool-results/<sha256>`), and rewrites the inline block as a `<tool-result file="..." preview-lines="..." command="..." original-body-tokens="...">` reference with a small leading-line preview. The cache key is `SHA-256(command + 0x1F + input)` (full 64-hex digest, ASCII unit-separator); identical tool calls across dispatches reuse the existing cache file with mtime preserved (cache-prune.sh ages it correctly in T02). Hooks fire BEFORE `cat $PAYLOAD_CAPTURE` so the dispatched agent receives paged bytes, and BEFORE `_bc_emit_payload_breakdown` so payload sizing reflects post-tier1 reality.

`_bc_emit_payload_breakdown` gains two additive integer fields per CON-5: `tier1_savings_tokens` and `tier1_invocations`. Pre-T01 records remain valid JSON; rollups treat missing fields as 0. The function also wires in P02's `pres_check_section` (sourced from `scripts/lib/preservation-check.sh`) over the rewrite — on failure, the pre-paging body is restored, stats are zeroed, and a `tier_preservation_violation` JSONL record is emitted via `pres_emit_violation`. Dual disable contracts honored: `compression.enabled: false` short-circuits the entire pipeline (P02 byte-identity golden preserved); `compression.tier1.enabled: false` short-circuits tier1 only — knowledge filter still runs.

Four new config keys land in both `.orchestrator/config.yml` and `templates/orchestrator-config-default.yml`: `compression.tier1.enabled` (true), `compression.tier1.inline_threshold_tokens` (1500), `compression.tier1.preview_lines` (5), `compression.tier1.cache_dir` (`.orchestrator/cache/tool-results/`). The awk parser in `kf_read_compression_scalar` was extended to recognize `tier1.*` nested keys; four new sourceable accessors follow the established `kf_get_*` pattern.

Verification: synthetic fixture with one oversized tool-result block compressed 33203 → 481 bytes (savings_tokens=8205, invocations=1); second pass reused the cache file with mtime preserved; both disable contracts passed cleanly. Live build-context dispatch against M018/P02/T01-preservation-check-lib emitted a payload_breakdown record carrying `tier1_savings_tokens=0` + `tier1_invocations=0` (no oversized blocks present) plus all pre-T01 fields. All six P02 verifiers still PASS, confirming no regression. T02 ships `cache-prune.sh`; T03 ships the five P03 verifiers + fixture; full P03 must-haves verifiable then.
