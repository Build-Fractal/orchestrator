T02 extends three [M027](../../../../../milestones/M027/index.md) diagnostic surfaces additively to surface the four M018 compression-savings fields landed by T01.

scripts/diagnostics/metrics-rollup.sh: the normalize-stage awk pass projects four new pipe-fields (filter_dropped_tokens / tier1_savings_tokens / tier2_savings_tokens / tier1_invocations) at projection columns 13-16 from each JSONL record uniformly. The aggregate-stage awk pass accumulates per-scope sums from payload_breakdown rows ONLY (skipping the rolled-up copies T01 added to dispatch_usage / unit_close to avoid double-counting), keyed by the target-granularity scope key. The render stage appends FILTER_DROPPED / TIER1_SAVINGS / TIER2_SAVINGS / TIER1_INVOCS columns after the existing 12, preserving column indices 1-12 byte-identical for back-compat consumers (CON-5 carry-forward to the rollup column-index contract).

scripts/diagnostics/efficiency-footer.sh: appends a `compression: <pct>% reduction over baseline (filter+tier1+tier2 / payload_tokens)` line when tokens > 0 AND pct >= 0.5 (rounding-noise floor) AND `compression.efficiency_footer.enabled` is not falsy (env-var ORCH_COMPRESSION_FOOTER overrides config). The line is suppressed entirely when all savings are zero, when the new knob is false, or when --quiet (parent footer suppressor) fires. The awk extractor handles the `(N missing)` EST_COST_USD column-shift by detecting the leading `(` on column 5 and reading TOKENS_EST at column 7 / savings at columns 15-17 in the shifted case.

scripts/diagnostics/check-anomalies.sh: extends the per-task awk extraction to capture TOKENS_EST + the four savings columns and computes savings_ratio = (fdrop + t1s + t2s) / tokens per row. Adds a fourth reason `compression-regression` composed additively with the existing cost-spike / retry-spike / low-pass-rate reasons when ratio < `compression.regression_floor` (default 0.347, SC-9 P00-calibrated) AND sav_total > 0 (the latter guard distinguishes "compression ran and underperformed" from "compression did not run at all", so pre-P05 records and disabled-pipeline runs do not falsely trip every row). Flagged rows surface `savings_ratio=<r>` alongside the existing cost/pass_rate/retry_count tokens. The same column-shift logic for `(N missing)` carries over (savings cols shift +2 just as pass_rate / retries already did).

Config knobs registered: `compression.efficiency_footer.enabled` (default true) and `compression.regression_floor` (default 0.347), both added to `templates/orchestrator-config-default.yml` and `.orchestrator/config.yml`. The `kf_read_compression_scalar` awk parser in `scripts/lib/knowledge-filter.sh` gained an `in_ef` branch (parallel to in_kf / in_up / in_t1 / in_t2) so dotted keys `efficiency_footer.enabled` / `regression_floor` parse correctly. New helpers `kf_get_efficiency_footer_compression_enabled` and `kf_get_compression_regression_floor` follow the established kf_get_* shape (default `true` for booleans, default 0.347 for the floor scalar). `scripts/state/read-config.sh` gained the two dotted keys in VALID_KEYS and dispatches to the kf_get_* helpers post env-var precedence — preserving the plan-mandated `bash read-config.sh compression.<key>` caller surface that efficiency-footer.sh and check-anomalies.sh use.
