M020 graduates the orchestrator's flat MEM knowledge registry into a queryable, reviewable, clusterable substrate. Across six phases the milestone landed (1) a closed-enum `status:` field schema authority gate with companion `decision_history:` + `archived_into:` fields, (2) a deterministic dispatch-callable read-only query surface, (3) a candidate->graduate cluster workflow with multi-entry atomicity and decision-history append, (4) a Review-Queue surface in `orchestrator:status` with staleness flags, (5) Jaccard clustering inside `orchestrator:consolidate` with conflict-as-advisory diagnostics, and (6) an operator preferences cascade (project > user > built-in default per key) that backs both the query state-filter and the consolidate similarity threshold. Together these surfaces close the spec-025 user stories US-1..US-5 (with the read-only dispatch invariant FR-8/CON-1 holding throughout) and stand up a stable schema contract that downstream milestones ([M024](../../milestones/M024/index.md) routing, [M019](../../milestones/M019/index.md) Tier 2+3 observability, [M018](../../milestones/M018/index.md) context-compression) can consume without further coordination.

P01 (foundation) shipped the schema-authority gate via [`.orchestrator/DECISIONS.md`](../../decisions.md) D024 + [`knowledge/conventions/MEM031.md`](../../knowledge/conventions/MEM031.md) documenting the `status:` closed enum (`candidate`/`graduated`/`archived`) plus the FR-10 default that absent `status:` reads as `graduated` (no bulk migration). It landed `scripts/knowledge/lib/frontmatter.sh` (atomic tempfile+rename writes, closed-enum guard runs BEFORE tempfile creation so invalid values produce zero file I/O), the minimum-viable `scripts/knowledge/graduate.sh --rationale '<text>' <entry-id>` (single-entry candidate->graduated flip, idempotent NO-OP on already-graduated, archived rejected), and `scripts/knowledge/lib/jaccard.sh` (pairwise primitive: tokenize -> sort -u -> comm -12 -> awk floating division, no `bc` dependency). The `validate` subcommand walked the live tree (31 entries, 465 pairs, top similarity 0.2000) and produced `phases/P01/jaccard-validation-report.md` with an adaptive threshold recommendation: top observed similarity < 0.3 -> aggressive lowering AND a flag that the CON-5 v1 feature vector was too narrow, recommending P05 widen it. This data-driven recommendation became P05's marching order rather than a guess.

P02 (query surface) delivered `scripts/knowledge/query.sh` implementing FR-2 sub-clauses (a)-(f) deterministically: case-insensitive whole-string topic exact-match, case-folded `tags[]` membership, two-tier ranking (topic-field above tag-only, ties broken by `last_verified` desc), default `--state graduated` filter, and `--format ids|json` outputs (ids default, grep-friendly; json single-document with matches array for richer callers). A 12-line early-exit-passthrough guard inside `scripts/dispatch/dispatch-interface.sh --query` exec-bridges to query.sh with byte-equivalent stdout/stderr/exit and bypasses the dispatch-usage JSONL emitter (FR-8/CON-1). The `tests/test-knowledge-query.sh` integration test (233 lines, MEM002-conformant) covers SC-1 + SC-7 via pre/post md5+mtime snapshots across a 7-invocation battery -- strictly stronger than `git status` because it catches in-place rewrites that round-trip byte-for-byte.

P03 (graduate workflow + schema-authority lint) extended `graduate.sh` in place with `--cluster <id>` + `--reject` + multi-entry positional shape. The cluster-aware mutation script pattern is the load-bearing P03 contribution: pre-flight `fm_read_status` on every member at graduate-time (not at cluster-time per THREAT-006 disposition), abort with structured `cluster-membership-drift` diagnostic + zero file mutations on any non-`candidate` member, then deterministic write loop with shared per-cluster scalars (operator, rationale_hash, canonical), then JSONL emission after all writes succeed. Drift-gate-as-CON-4-preserver: gating the new pre-flight on the new flag means legacy single-entry invocations pay no cost. `scripts/knowledge/lib/decision-history.sh` exposes `dh_resolve_operator` (git config user.email -> preferences.yml:operator_identifier -> unknown@local fallthrough per OQ-2) and `dh_emit_jsonl` (one JSON object per call, conservative escape, no jq dependency). `scripts/verify/knowledge-schema-lint.sh` enforces FR-9 + SC-8 with three failure shapes (unauthorized-field, vocabulary-drift, malformed-frontmatter); live tree scan: 31 entries / 0 violations.

P04 (review queue) extended `scripts/knowledge/compute-staleness.sh` in place with `--review-queue` + `--knowledge-root <path>` flags (legacy invocations preserved byte-equivalent), and extended `scripts/orchestrator/status.sh` with a `Review Queue:` section emitted after the per-milestone enumeration. The renderer subprocess-invokes the helper and is failure-tolerant via tempdir + RETURN trap + four guard branches (rc!=0, EMPTY, empty-output, malformed-line) each emitting `Review Queue: unavailable` + one-line stderr diagnostic, with `status.sh` exit always 0. Stale flag resolves at default 14 days (OQ-1) with preferences override; topic field whitespace-collapsed; age uses `created_at:` then `last_verified:` fallback. The integration test adopts the shadow-repo + wrapper-helper pattern so the live cluster.sh + jaccard.sh + frontmatter.sh + staleness.sh pipeline runs end-to-end against tempdir fixtures while leaving live `knowledge/` and `.orchestrator/execution-log.jsonl` untouched.

P05 (clustering) delivered `scripts/knowledge/lib/cluster.sh` exposing `cluster_compute <root> <threshold>` (walks candidates, computes pairwise Jaccard via subprocess invocation of jaccard.sh, runs union-find on the similarity graph, emits sorted `<cluster-id>\t<member-id>` lines including singletons) and `cluster_id_for <sorted-csv>` (deterministic AD-3 `C<8-hex-of-sha1>`). T01 caught and corrected a reference-implementation drift: the payload's `. jaccard.sh` source pattern would have killed the host shell because of jaccard.sh's file-scope `set -euo pipefail` + bottom-of-file empty-subcommand-exit; substituted subprocess invocation while preserving the documented external contract. T02 implemented exactly the three vector extensions P01 named (`relates_to[]` + `source_unit` frontmatter + body cap 200 tokens) and used capture-validate-restore to preserve the P01 deliverable byte-equivalent (CON-4) while regenerating a P05-tagged report. T03 extended `scripts/knowledge/consolidate-artifacts.sh` with a `--cluster` short-circuit that emits `cluster_id=<C8hex>` + indented `member=` blocks, surfaces an advisory `conflict: cluster=<id> reason=divergent-decision-history` line on mixed-history clusters (no abort -- mutation gates live in graduate.sh per THREAT-006), and appends one `consolidate_cluster` JSONL record per cluster.

P06 (preferences) shipped `scripts/knowledge/lib/preferences.sh` exposing `pref_resolve <key>` for the FR-6/US-5 cascade. Closed-enum key vocabulary {`default_state_filter`, `similarity_threshold`, `staleness_threshold`, `preferred_cluster_size`, `operator_identifier`} with built-in defaults (`graduated`, 0.7, 14, 8, `unknown@local`) and per-key validators. THREAT-007 disposition: each key resolves independently with project > user > built-in-default precedence (partial overlaps land cleanly). Malformed values fall back to next source per the precedence chain with a single-line stderr `WARN` diagnostic naming key + offending value + selected fallback; the preferences file is NEVER mutated. AD-5 grep+sed YAML parsing keeps the helper yq-free. The deferred-resolution sentinel pattern (empty-string sentinel + seen-on-cli flag set in the CLI arm + post-argparse pref_resolve cascade) is how `query.sh` and `consolidate-artifacts.sh` integrate: CLI > project > user > built-in default. Cross-cutting patterns established by M020 fall into five families. (1) Schema-authority discipline: D-row + conventions MEM lands BEFORE any code touches the schema; closed-enum guards run before file I/O; companion fields (`status:`/`decision_history:`/`archived_into:`) are documented together; `knowledge-schema-lint.sh` is the canonical gate. (2) Read-only-during-dispatch invariant: every M020 surface that runs at dispatch-time (query.sh, dispatch-interface --query) holds md5+mtime byte-equivalence across multi-invocation batteries; mutations live only in operator-invoked entry points (graduate.sh, consolidate-artifacts.sh --cluster). (3) Atomic-and-additive in-place extension: gate new behavior on a new flag (`--review-queue`, `--cluster`, deferred-resolution sentinel) so legacy invocations exhibit zero behavior delta; CON-4 byte-equivalence is preserved by inspection plus regression tests against prior-phase integration suites. (4) Plan-deviation invariant for verifiers: any task whose plan names a verifier in its Verification section MUST author it inline -- auto-loop `--step=V` runs verifiers at task close with no cross-task ordering awareness (T01/T02 deviations carried forward through P04). (5) Capture-validate-restore for byte-equivalent preservation of upstream-phase deliverables (P05/T02 preserved P01's `jaccard-validation-report.md`).
