T01 authored the load-bearing M035/P03 deliverables: `packaging/homebrew/orchestrator.rb.tmpl` (the Homebrew formula template) + `packaging/homebrew/render-formula.sh` (the bash 3.2 token-substitution driver) + the D007 row in [`.orchestrator/DECISIONS.md`](../../../../../decisions.md) + the two task-grain shape verifiers under `tools/verify/m035-p03-*.sh`.

The formula template is intentionally minimal per FR-9: `class Orchestrator < Formula` with `desc` + `homepage` + `url` + `version` + `sha256` + `license "MIT"`, a `def install` that does filesystem staging only (`prefix.install Dir["package/*"]` to unwrap npm's `package/` tarball convention + `bin.install_symlink prefix/"bin/orchestrator"` to wire the binary onto PATH), and a `test do` block that asserts `orchestrator --version` matches the formula's `version` field (Homebrew-conventional smoke + SC-9 binding). Three anti-patterns are explicitly excluded: no `depends_on "node"`, no `depends_on "python@3"`, no `on_macos` / `on_linux` split. node + python3 are operator-installed (or provided by Homebrew itself when the operator already has them); declaring hard `depends_on` would force brew to install dependencies that may already be present, causing install friction without value. The runtime is shell + markdown, identical across both platforms.

`packaging/homebrew/render-formula.sh` is a bash 3.2-compatible flag-parsing driver: while-loop case-statement consumption of `--version` / `--url` / `--sha256`, three required-flag guards, a 64-hex-lowercase shape validation on the sha256 (`printf '%s' "$SHA256" | grep -qE '^[0-9a-f]{64}$'`), a `SCRIPT_DIR` resolution (`cd "$(dirname "$0")" && pwd`) for the template lookup, and a single `sed -e s|__TOKEN__|value|g` substitution pass that emits the rendered formula on stdout. The `|` delimiter is used because URLs contain forward slashes; the URL is defensively `|`-escaped before substitution. No `<(...)` process substitution, no `$(...)` containing pipes, no plain subshells in command position — AP-009 honored throughout.

D007 records the cross-channel binding: the homebrew formula's `url` field points at the same `build-fractal-orchestrator-<version>.tgz` artifact that P02's `npm-publish` job + P05's signing pass publish on the GitHub release. NO separate brew-tarball is built. Three rationale legs: (1) CON-5 byte-equivalence is structural — a separate brew-tarball would introduce an independent build path whose hash drift versus the npm tarball would mask the very divergence CON-5 exists to catch; (2) single signing chain — P05's cosign + SHA256SUMS pass already covers the npm tarball, so re-using it means the formula's `sha256` is sourced from the same `SHA256SUMS` file with no duplicate signing surface; (3) CON-6 secret-scoping carries over — the `homebrew-publish` job consumes the published tarball URL + SHA-256, no fresh build, no fresh secrets, just `secrets.HOMEBREW_TAP_TOKEN` for the cross-repo write into `build-fractal/homebrew-orchestrator`.
