The installer's production path resolves `VERSION=latest` via a jq-free `grep -E '"tag_name"' | head -1 | sed -E 's/.*"tag_name".*"([^"]+)".*/\1/'` parse of `api.github.com/repos/<REPO>/releases/latest`, derives the asset name `build-fractal-orchestrator-<TAG_NO_V>.tgz` from the npm scope `@build-fractal/orchestrator` (P02 T01 contract), downloads both the tarball and `SHA256SUMS` from the same release, runs `shasum -a 256 -c SHA256SUMS --ignore-missing` to verify integrity (the `--ignore-missing` flag matches P05 T04's `references/installation.md § Verifying integrity` recipe — SHA256SUMS lists multiple artifacts and the operator only has the one downloaded), extracts via `tar -xzf` into a `mktemp -d` staged dir, flattens the npm `package/*` convention via `cp -R + rm` (exotic-FS robust over `mv`), and dispatches `bash <STAGED>/packaging/install/install-claude-code.sh --project-dir "$ORIG_PWD"`.

CC-only at v1 per the launch posture: the runtime-detection block tests `[ -d "$HOME/.claude" ]` and exits with code 2 + a "Codex CLI / Cursor support is post-launch (M009 fast-follow); see references/installation.md" advisory on absence. Exit codes form a structured contract: 0 success, 1 generic failure, 2 unsupported runtime, 3 download/SHA-verify failure. The `set -eu` discipline (not `set -euo pipefail` per Bash 3.2 paper-cuts noted in the plan-phase Notes block) is reinforced with explicit `|| { echo FAIL; exit N; }` failure handlers around the SHA-verify pipe and the tarball extract.

Test-mode env-var hooks are load-bearing for T03's byte-equivalence test: `M035_P04_LOCAL_TARBALL=<path>` short-circuits the download + SHA-verify chain (operator-supplied tarball stands in for the GitHub release asset); `M035_P04_STAGE_ONLY=1` exits 0 with `STAGED_DIR=<path>` on stdout after extract (skips the install-claude-code.sh dispatch + suppresses the cleanup trap so T03 can hash the staged tree); `M035_P04_STAGE_DIR=<path>` overrides the random `mktemp -d` so T03 can hash a deterministic path. All three default-OFF: the production path is byte-identical when env vars are unset, mirroring P05's `COSIGN_AVAILABLE=1 + M035_P05_LIVE_RELEASE_DIR=path` precedent.

D009 records the URL-host decision: `install.sh` is hosted as a GitHub release asset (`https://github.com/Build-Fractal/orchestrator/releases/latest/download/install.sh` for unpinned + `releases/download/v<X.Y.Z>/install.sh` for pinned), NOT on `orchestrator.dev`, github.io, fly.io, R2-backed CDN, or the canonical-repo `/raw` URL. Four rationale legs: (1) zero new infrastructure surface — every alternative requires either a new domain, a new hosting provider, or a stable-mainline-commit-SHA strategy; (2) symmetric with D007's npm + homebrew release-asset distribution model; (3) versioned + unversioned URLs both ship for free; (4) reversible — wiring a polished short URL post-launch is a one-line DNS change.
